## ① · ⑥ 폰트 크기 — **새 페이지가 기존 페이지보다 훨씬 작다**

텍스트를 «직접 가진» 요소만 세어 화면별 분포를 냈다.

| 화면 | 9px 미만 | 최빈 크기 | 단계 수 | 최소 |
|---|---|---|---|---|
| **대시보드(9차)** | **53 / 169 = 31%** | 9.5px | 17 | **5.5px** |
| **히트맵(9차)** | **57 / 122 = 47%** | 10px · **6px가 20개** | 12 | **6px** |
| 가디언 | 15 = 10% | **12px** (49개) | 16 | 8px |
| 커맨드 | **3 = 2%** | **11px** (53개) | 20 | 8px |

→ 「다른 페이지와 폰트가 다르다」는 지적이 **정확하다.**
커맨드 최빈 11px · 가디언 12px 인데 **대시보드 9.5px · 히트맵은 6px 가 20개**다.
같은 앱 안에서 **1.5~2 단계** 차이가 난다.

### 업계 표준
| | 가장 작은 «정의된» 글자 |
|---|---|
| Apple HIG (iOS) | **Caption 2 = 11pt** |
| Material Design 3 | **labelSmall = 11sp** |

우리 9차의 7.5 · 8 · 8.5px 는 **양대 플랫폼이 정의한 최소보다 작다.** 6px 는 그 절반이다.
→ 대표 감각이 맞다. **작다.**

## ② 전체 1단계 올리면 구조가 틀어지나 — **그렇다, 그러나 «막을 수 있다»**

9차 CSS 는 고정 폭 칸으로 짜여 있다(티커 44px · 등락률 50px · 가격 64px ·
섹터 카드 104px · 뱃지 14px …).

```
고정 폭 개수   dash9 37 · 히트맵 12 · 랭킹 9 · 무버 8 · 실적 6   = 72곳
폰트 선언      dash9 만 72개 / 17단계
```

**권고**: 전체 +1 이 아니라 **가장 작은 층만** 올린다 —
`5.5·6·7·7.5 → 9` , `8·8.5 → 9.5~10`. 큰 글자는 그대로.
가장 안 읽히는 곳이 가장 많이 좋아지고, 고정 폭 충돌은 최소가 된다.

## ⑨ 「9차 카드가 왜 더 잘 읽히고 넓어 보이나」 — 실측된 이유 4개

대표 관찰: 「이번에 작업한 대시보드 카드가 가독성도 좋고 넓어 보인다. 왜 그런지 모르겠다」
색이 아니라 **구조 4가지**다. 둘을 나란히 재면 이렇게 나온다.

| | **9차 (오늘의 발견·무버)** | **커맨드 (상관 종목)** |
|---|---|---|
| 행이 «상자»인가 | 배경 **없음** · 테두리 **0** · 반경 **0** | 배경 있음 · 테두리 **1px** · 반경 **10px** |
| 나누는 법 | **1px 헤어라인** `rgba(255,255,255,.05)` | 상자 + 간격 |
| 칸 정렬 | **고정 칼럼** `0 0 46px` / `0 0 22px` / `0 0 42px` | 전부 `0 1 auto` (내용 길이대로) |
| 카드→행 폭 손실 | **24px** (358 → 334) | **34px** (358 → 324) |
| 행 높이 | **31~34px** | **54px** |

### 왜 그 4가지가 «넓어 보이게» 만드나
1. **행마다 상자를 그리지 않는다.** 상자가 12개면 눈이 경계 12개를 센다.
   헤어라인이면 «목록 하나»로 읽힌다. 경계가 줄면 면이 넓어 보인다.
2. **숫자가 세로로 줄을 맞춘다.** 고정 칼럼이라 티커·값·상태가 «열»을 이룬다.
   `0 1 auto` 는 종목마다 값 위치가 달라져 눈이 좌우로 흔들린다.
3. **한 줄에 다 넣었다.** 같은 정보가 54px → 34px. 40% 낮다.
4. **중첩 손실이 10px 적다.** 커맨드는 카드 패딩이 16px 라 겹칠 때마다 34px 를 잃는다.

→ **다른 페이지에 옮길 때 색은 그대로 두고 이 4가지만 가져가면 된다.**

## ⑩ 「넘친 곳만 넓힌다」 — 틀어지지 않게 할 수 있나

**기계가 재는 부분은 «빠짐없이» 보장할 수 있다.** 절차:
```
1) 가장 작은 층만 올린다        5.5·6·7·7.5 → 9   /   8·8.5 → 9.5~10
2) 3언어 × 전 화면에서 «잰다»    잘린 글자(scrollWidth>clientWidth) · 가로 스크롤
3) 넘친 «그 칸만» 넓힌다         고정 폭 72곳 중 실제로 걸린 것만
4) 다시 잰다                     0 이 될 때까지 반복
5) 화면 캡처로 눈 확인            기계가 못 보는 «어색함»은 대표가 판단
```
보장되는 것: **잘린 글자 0 · 가로 스크롤 0** (이미 이 검사로 영어 라벨 3개를 잡았다)
보장 못 하는 것: 미적 판단 — 그래서 마지막에 캡처를 드린다.

⚠️ **정직하게 남길 트레이드오프**: 글자가 커지면 카드가 **세로로 길어진다.**
한 화면에 들어가는 항목이 줄어든다. 이건 잘림이 아니라 선택의 문제다.
(예: 히트맵 «오늘의 양 끝» 8행이 7행이 될 수 있다)
