## 2. 무엇을 바꿨나

### 2-a. EC2 프록시 `readBody` (커밋 ccea343c6, 09-18 배포·검증 완료)
`body += chunk` 가 TCP 청크 경계의 다바이트 UTF-8 을 깨뜨렸다 → `Buffer.concat`. 회귀검사 153개 절단점: 옛 코드 60 실패 → 새 코드 0. 배포 후 1.2KB~146.5KB 한/일 값 스윕 전부 ✓. **이것이 대역폭의 원인이었고, 7/1 의 폴백은 이제 «거의 발동하지 않는» 안전장치로만 남는다.**

### 2-b. `src/services/redisClient.ts` 정책 (커밋 79a3248a9)
| 상황 | 예전 | 지금 |
|---|---|---|
| 쓰기 — TTL 있는 래퍼 캐시 키(`intrinio:resp:*`, `cache:*` 등 대부분) | EC2 + Upstash | **EC2 만** |
| 쓰기 — TTL 없는 내구 키(`mkt:*`, `trade:*`, `push:*`…) | EC2 + Upstash | EC2 + Upstash (그대로) |
| 쓰기 — 장애-필수 접두사(`guardian:*`, `vix:*`, `*:lastgood:*`…) | EC2 + Upstash | EC2 + Upstash (그대로) |
| 쓰기 — `flow:ticker:lastgood:*`(257KB) / `intrinio:snap:lastgood:*` | 매번 Upstash 에도 | EC2 매번, Upstash 는 키당 5분/1분에 1회 |
| 쓰기 — EC2 실패 | Upstash | Upstash (그대로) |
| 읽기 — EC2 값 있음 | EC2 | EC2 (그대로) |
| 읽기 — EC2 «정상 응답으로 null», 래퍼 키 | Upstash 를 되물음(유료, 46% 만 적중) | **묻지 않고 미스 처리** |
| 읽기 — EC2 null, Upstash 전용/복제 접두사(`cache:13f`, `push:`, `guardian:`…) | Upstash | Upstash (그대로) |
| 읽기 — 프록시 401/타임아웃/쿨다운/깨진 값 | Upstash | Upstash (그대로) |

핵심 장치: `ecProxyGetEx()` 가 `{ok, value}` 를 돌려 «미스»와 «프록시 이상»을 구분한다. 프록시 이상이면 예전과 «완전히 같은» 경로다. 정책은 순수 함수(`decideReplicate`, `shouldFallbackToUpstash`)라 테스트가 고정한다.
