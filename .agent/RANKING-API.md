# 랭킹 API — 다른 에이전트(윈도우 등)에게 넘길 것

## 왜 코드가 아니라 주소인가

생성기는 DynamoDB·EC2 Redis 를 직접 읽는다. 코드를 복사해 주면 **AWS 키까지
넘어가야 한다.** 그러면 안 된다. 그리고 두 벌로 갈라지면 어느 날 조용히
달라지고, 그때 어느 쪽이 맞는지 알 수 없다.

**구현은 이 저장소 한 곳(`src/app/api/ranking/deviation/route.ts`)에만 둔다.
윈도우는 주소만 부른다.**

## 주소

```
https://www.signumhq.com/api/ranking/deviation
```

| 파라미터 | 기본 | 설명 |
|---|---|---|
| `top` | 5 | 상위 몇 개 (1~10) |
| `days` | 30 | 기준선 기간 (10~90) |
| `refresh` | — | `1` 이면 캐시 무시 (평소엔 넣지 말 것 · 캐시 10분) |

인증 없음. GET 하나면 끝.

## 응답 예

```json
{
  "ok": true,
  "generatedAt": "2026-09-01T00:12:00.000Z",
  "darkPool": { "available": false, "stale": true,
                "date": "2026-08-28", "expected": "2026-08-31",
                "reason": "아직 안 들어옴 — ..." },
  "candidates": 7,
  "ranking": [
    { "ticker": "UNH", "metric": "squeezeProbability",
      "label": { "ko": "스퀴즈 확률", "en": "Squeeze probability", "ja": "スクイーズ確率" },
      "today": 50, "baseline": 23, "ratio": 2.17, "z": 4.1,
      "sessions": 9, "date": "2026-08-31" }
  ]
}
```

## 쓰는 쪽이 반드시 지킬 것

1. **`ranking` 이 비어 있을 수 있다.** 게이트를 다 통과한 게 없으면 빈 배열이다.
   그때는 «영상을 만들지 않는다». 억지로 채우면 그게 거짓말이 된다.
2. **`darkPool.available` 을 반드시 본다.** `false` 면 다크풀은 랭킹에 없다.
   FINRA 는 마감 후 약 90분(17:30 ET = 06:30 KST)에 들어온다.
   `stale: true` 는 «옛날 것을 들고 있다»는 뜻이지 «오늘 것이 있다»가 아니다.
3. **`baseline` 을 항상 같이 보여준다.** 「평소의 2.2배」만 쓰면 검증할 수 없다.
   오늘값·평소값·배수 셋을 같이 낸다.
4. `label` 은 ko/en/ja 가 다 온다. 영상 언어에 맞는 것을 쓴다.

## 축 (지표) 목록

옵션 7축 + 다크풀 2축. **랭킹은 하나**이고, 이 축들에서 나온 후보를
「평소의 몇 배」로 한 줄 세운다. 종목당 1개만 올린다(한 종목이 독식하지 않게).

| 축 | 출처 |
|---|---|
| 풋콜 비율 · 콜/풋 미결제약정 · 대형거래 지표 · 델타 노출 · 스퀴즈 확률 · 옵션 자금 | DynamoDB `signum-flow-history` |
| 장외 거래량(평소의 몇 배) · 장외 공매도 비중(평소 대비 %p) | FINRA (마감 후 90분) |

## 이 랭킹이 «절대 순위»가 아닌 이유

옵션 프리미엄 TOP 같은 절대 순위는 시가총액을 따라가서 NVDA·TSLA·AAPL 이
거의 매일 상위다. 답을 미리 아는 랭킹은 볼 이유가 없다. 다크풀도 같다 —
시장 전체 공매도 비중 중앙값이 **49%** 라 절대값은 아무 말도 안 한다.
정보는 «그 종목 자신의 평소 대비 이탈»에만 있다.
