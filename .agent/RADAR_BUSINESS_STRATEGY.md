## 0. 한 줄 결론

**레이더는 "광고로 돈 버는 앱"이 아니라 "포트폴리오에서 유일하게 하루 여러 번 열리는 앱"이다.** 광고는 운영비를 덮고, 진짜 매출은 SIGNUM 구독 전환에서 나온다. 그리고 지금 레이더는 **보유 자원의 1.4%(211개 API 중 3개)만 쓰고 있다** — 여기가 가장 큰 기회다.

## 1. 광고 기반 비즈니스 전략

### 1.1 먼저 인정할 것 — 광고 단독으로는 사업이 안 된다

광고 매출 = `DAU × 세션/일 × 노출/세션 × eCPM`

⚠️ **eCPM 실측치는 우리에게 없다**(SPINOFF4 §정직한 공백에서 이미 검증 실패로 기록됨). 아래는 **가정 기반 모델**이며 첫 코호트로 실측해 교체해야 한다.

| 가정 | 값 |
|---|---|
| 세션/일 | 3 (푸시 2 + 자발 1) |
| 배너 노출/세션 | 1.5 · eCPM $1.5 |
| 전면 노출/세션 | 0.2 · eCPM $9 |
| 리워드 노출/세션 | 0.05 · eCPM $20 |
| 세션당 기대수익 | **$0.005** |

| DAU | 월 광고 매출(모델) |
|---|---|
| 1,000 | ~$450 |
| 5,000 | ~$2,250 |
| 10,000 | ~$4,500 |

**판단**: 신생 앱이 1년 안에 DAU 10,000을 만들 확률은 낮다. **광고는 서버비·데이터비를 덮는 수단으로 설계하고, 매출 기대는 SIGNUM 전환에 둔다.**

### 1.2 설계상의 치명적 긴장 — "3초 체크"는 광고와 상극이다

레이더의 핵심 컨셉은 *3초 확인*이다. 그런데:
- 배너는 **체류 시간**이 있어야 노출가치(viewability)가 생긴다
- 전면광고를 3초 세션에 끼우면 **UX 파괴 + 이탈**
- 3초 세션 × 하루 3회 = 하루 9초 = 광고가 붙을 자리가 사실상 없다

**→ 해결책: "3초 확인" 다음에 "30초 머물 이유"를 붙인다.** 습관은 3초가 만들고, 수익은 그 뒤 30초가 만든다.

### 1.3 광고 포맷별 배치 설계 (이미 인프라 보유)

`src/services/adManager.ts`에 **3단 파이프라인이 이미 구현돼 있다** — 배너/전면/리워드 + 빈도 거버넌스(연속 전면 방지) + UMP 동의폼(EEA/UK) + Pro 사용자 배너 억제. **신규 개발 0.**

| 포맷 | 배치 지점 | 근거 |
|---|---|---|
| **배너** | 홈 하단 고정 | 이미 `AppBottomNav`가 배너 자리(60px) 확보 |
| **전면** | 탭 전환 3회마다 1회 / 상세→뒤로 시 | 자연스러운 전환점. 3초 체크 흐름은 절대 막지 않음 |
| **리워드** ★ | **워치리스트 슬롯 확장** (무료 5종목 → 광고 시청 시 +3), **알림 임계값 커스텀 해제** | 유틸리티 앱에서 사용자가 가장 잘 수용하는 교환. eCPM도 가장 높음 |

**리워드가 레이더의 핵심 수익 포맷**이다. 워치리스트는 이 앱의 락인 장치이자 자연스러운 유료 게이트다.

### 1.4 진짜 사업 구조 — 포트폴리오 관점

```
레이더 (하루 2~5회 열림)  ← 포트폴리오에서 유일한 고빈도 접점
   │
   ├── 광고         → 운영비 커버
   ├── SIGNUM 전환  → $9.99/월 구독 ★ 실제 매출
   └── UC/WIM 유입  → 상호 리텐션
```

- 레이더 사용자가 "왜 이 레벨이 중요한가"를 더 알고 싶어지는 순간 = **SIGNUM 상향 퍼널**
- 전환율 1%만 나와도 DAU 5,000 → 50명 × $9.99 = **$500/월**, 광고와 맞먹고 **마진은 훨씬 높다**
- **레이더의 진짜 KPI는 광고 매출이 아니라 SIGNUM 전환 수**

### 1.5 AdMob 현실 제약 (기록 반영)

- AdMob 계정 승인 게이트 = **W-8BEN 세금 심사**. 재신청 완료 상태(거주자증명서 첨부).
- **세금 승인 전에는 광고 활성화 불가** → 레이더 v1도 UC/WIM과 같이 **광고 OFF로 제출**, 승인 후 1.0.1에서 활성화.
- 이는 오히려 유리하다: v1은 "광고 없는 깨끗한 앱"으로 초기 평점을 벌고, 습관이 자리 잡은 뒤 광고를 넣는다.

## 3. 시장성

### 3.1 검증된 사실 (SPINOFF4_RESEARCH 인용)

1. **금융앱 성장은 설치가 아니라 세션이 주도** (2025 Q3 설치 +11% vs 세션 +16%) → 고빈도 전략이 시류에 맞음
2. **Unusual Whales의 구멍**: 딜러 레벨 **가격-크로스 푸시 알림 없음**, 무료 광고층 없음(구독 $9.99~$719.99), 모바일 트랙션 약함(US 평점 590 vs X 팔로워 400만)
3. **KR**: QuantView — 무료지만 공개지표만, 평점 0
4. **JP**: Kaview — ¥1,180/월, **하루 1회 15:30 배치 갱신** → 장중 습관 공백 실증
5. **"기관 데이터 × 무료광고 × 푸시 유틸리티" 층 = 무점유**
6. **배당 수요는 한국 전유물 아님** — 일본 検証(配当管理 63만DL), 대만 대형(영어 병목 = 화이트스페이스)

### 3.2 우리의 실질 우위

| 축 | 경쟁사 | 레이더 |
|---|---|---|
| 알림 | UW 없음 | **레벨 크로스 + 6종 이벤트** |
| 가격 | UW $9.99~719 / Kaview ¥1,180 | **무료 + 광고** |
| 갱신 | Kaview 일 1회 배치 | **장중 실측** |
| 언어 | UW 영어 단일 | **ko/en/ja 3언어** |
| 데이터 | QuantView 공개지표 | **기관급(GEX·다크풀·맥스페인)** |

### 3.3 ⚠️ 정직한 리스크

- eCPM 실측치 없음 (수익 모델 = 가정)
- UW가 알림 기능을 붙이면 우위 상실 → **해자는 무료층 + 3언어 + KR/JP** 이지 기능 자체가 아님
- 배당 탭은 강력하지만 **레이더 컨셉과 이질적** — 사용자가 "이 앱이 뭐하는 앱이지?"로 혼란할 수 있음 (§4.3에서 다룸)

## 4. 메인화면 구성 — "텍스트가 아닌 매력"

### 4.1 현재 홈의 진단 (시뮬 실화면 기준)

**잘된 것**: 온도 게이지가 크고 즉각적이다. 실데이터 배지, 관찰 캡션 자동 생성, 로고 사용 — 텍스트 나열이 아니다.

**부족한 것**:
1. **"내 것"이 첫 화면에 없다.** 워치리스트는 레이더 탭에 있다 → 매일 열 개인적 이유가 홈에 없음
2. **시간 축이 없다.** "오늘 몇 시에 무슨 일이 있는지"가 안 보임
3. 게이지 아래는 결국 **카드 나열**로 흐름이 끊김
4. **배당 탭이 왜 여기 있는지** 설명이 없음

### 4.2 제안하는 홈 구성 (위→아래)

```
① 히어로: 온도 게이지 + 한 문장 관찰       ← 현행 유지 (강점)
     "27 냉각 · 풋이 콜보다 많고 숏볼륨 65%"

② ★ 내 종목 근접도 레일 (신규 - 레이더탭에서 승격)
     [AAPL ██████░░ 콜월까지 +0.4%]  ← 개인화, 매일 열 이유
     [SPY  ████████ 맥스페인 +0.2%]
     비어있으면 → "종목을 추가하세요" 온보딩 카드

③ ★ 오늘의 타임라인 (신규 - 경제캘린더+실적 결합)
     21:30  CPI 발표        (D-day)
     장마감  AAPL 실적       (D-4)
     → 시간 축이 "다시 열어야 할 이유"를 만듦

④ 오늘의 시그널              ← 현행 유지
⑤ 시장 하이라이트            ← 현행 유지
⑥ 이번 주 배당락            ← 현행 유지 (배당 탭 입구)
```

### 4.3 배당 탭 처리 — 정체성 문제

배당 기능은 **품질이 높고 시장성도 검증**됐지만(일본 63만DL 선례), 레이더의 "기관 레벨 알림" 정체성과 겹치지 않는다.

**두 가지 선택지 — 대표 결정 필요**
- **(A) 레이더 안에 유지**: 앱 정체성을 "미국주식 유틸리티 벨트"로 넓힌다. 장점=하나로 통합, 단점=포지셔닝 흐려짐, ASO 키워드 분산
- **(B) 5번째 앱으로 분리**: "배당 계산기"는 검색량 크고 경쟁 약한 독립 시장. 장점=ASO 명확, 단점=앱 하나 더 운영

**권고: (A) 유지하되 프레이밍을 바꾼다.** "배당"이 아니라 **"인컴"** 탭으로, 레이더의 서사에 편입 — *"기관이 어디서 움직이는지 보고(레이더), 내 돈이 얼마 들어오는지 본다(인컴)"*. 분리는 레이더가 자리 잡은 뒤 판단.

### 4.4 진입 첫인상 (설치 직후 3초)

앱을 처음 연 사용자는 **워치리스트가 비어 있다.** 이때 홈이 비면 이탈한다.

**해결**: 온보딩에서 **인기 종목 3개(AAPL·NVDA·TSLA)를 기본 워치리스트로 미리 채운다.** 첫 화면부터 근접도 바가 움직이는 것을 보여준 뒤, "내 종목으로 바꾸기"를 유도.

## 5. "자주 쓰는 앱" 설계 — 습관 루프

### 5.1 훅 모델 적용

| 단계 | 레이더의 구현 | 현재 상태 |
|---|---|---|
| **트리거** | 레벨 크로스 푸시 | ⚠️ 1종뿐 → **7종으로 확장 필요** |
| **행동** | 3초 온도 확인 | ✅ 완성 |
| **보상** | "왜 이 온도인가" — 가변적 보상 | ⚠️ 캡션 1줄 → 30초 읽을거리 필요 |
| **투자** | 워치리스트·임계값·스트릭 | ✅ 워치리스트 영속, 스트릭 있음 |

**가장 약한 고리 = 트리거와 보상.** 둘 다 §2.2의 미사용 자산으로 해결된다.

### 5.2 일일 리듬 설계 (ET 기준)

| 시각 | 푸시 | 여는 이유 |
|---|---|---|
| 개장 전 | "오늘 시장 온도 + 오늘의 일정" | 하루 준비 |
| 장중 | 레벨 터치 / 다크풀 블록 / 공시 (변동일수록 ↑) | 즉시성 |
| 마감 후 | "오늘 요약 + 내일 실적 D-1" | 마무리 |

→ **하루 2~5세션**이 설계로 보장된다. 이것이 UC(1회)·WIM(1회)와 근본적으로 다른 점이다.

### 5.3 락인 장치
