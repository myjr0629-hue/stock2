# 백로그 — 지금 안 하고 나중에 할 것

> 2026-09-02 대표 지시: 「지금은 앱 최적화이고 알파스코어는 지금 당장 사용할 곳이
> 없으니 일단은 계획에 옵션 웹소켓과 함께 넣어놔」

## ① 옵션 웹소켓 클라이언트 배선

**서버는 이미 완성돼 있다.** `scripts/intrinio-options-ws.js` + `ec2-price-ws.js` 가
OptionsEdge 에 붙어 **3,100만 건**을 받고 있고(구독 142종목·에러 0), `optionPrice`
타입으로 중계까지 한다.

**빠진 것은 두 개뿐이다:**
- `{type:'subscribeOptions', contracts:[...]}` 를 보내는 클라이언트
- 개별 계약 가격을 그리는 화면

**왜 미뤘나**: 표시할 화면이 없다. 그리고 같은 FMV 값을 실시간 그릭스 REST 가
이미 준다(실측: NVDA 223.57 일 때 220콜 mid 6.40 vs 전일종가 1.70).
웹소켓이 추가로 주는 것은 회전 주기(약 9분) «사이»의 틱 갱신뿐이다.

**착수 조건**: 옵션 체인 테이블이나 특정 계약 추적 UI 를 만들 때.
그때는 REST 폴링보다 확실히 낫다. 서버가 준비돼 있으니 클라이언트만 얹으면 된다.

⚠️ OPTIONS_EDGE 는 **가격만** 준다(size·bid·ask 전부 0). 체결 규모가 필요한
BLOCK/SWEEP 은 OPRA 상품이 있어야 한다. 없는 값을 지어내지 말 것.

## ② 알파스코어 — 이관 영향 백테스트

이관으로 입력 데이터가 바뀌었는데(다크풀·공매도가 FINRA 로, 그릭스가 실시간으로)
그 위에서 도는 알파스코어가 여전히 유효한지 **아무도 확인하지 않았다.**

**왜 미뤘나**: 대표 판단 — 「지금 당장 사용할 곳이 없다」.

**착수 조건**: 알파스코어를 화면이나 콘텐츠에 다시 쓰기 시작할 때.
그 전에 반드시 백테스트로 이관 전후를 대조할 것. 관련 람다는 `signum-harvest`
(`harvest_lambda/`, 506종목)로 옵션 수집기(`signum-flow-harvest`)와 **별개**다.
