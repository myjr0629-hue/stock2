# SIGNUM 앱 전용 워치리스트 — 기획서 (2026-09-29, 대표 지시)

> 대표 원문: «가장 중요한것은 웹용이 앱용이라는것 그리고 다른것과 다른 차별점 우리의 자원을 의미있게 해야한다는것이야 임팩트가 있어야 한다는것이야 구독해택도 그렇고 … 비지니스적으로도 유의미하게 … 계획부터 완벽하게 … 해당 폰에 저장하는것은 서버비용 그리고 속도면에서도 좋다 … 차별점과 고도화 부분을 완벽하게 균형잡고 알림까지 … 디자인도 당연한것이고»
> 상태: **계획 완성(작업 전)** — 외부 조사 2건(경쟁·알림/디자인/저장) 반영 · 화면 시안 v1 제시(9/29 00:3x)

## 0. 한 줄 정의
가격을 모아 보는 워치리스트가 아니라, **«내 종목의 기관·옵션 지형이 바뀌면 먼저 알려 주는» 포지셔닝 워치리스트**다.

## 1. 원칙
1. **앱 전용** — 앱 화면(app-view) 안에만 둔다. 웹 `/watchlist`(무료 5·pro 50·elite, 웹 로그인 등급)와 분리한다. 앱 구독 판정은 **RevenueCat «pro» 권한**(`useProStatus`)만 쓴다.
2. **폰 저장** — 목록의 원본은 기기다(즉시·서버비 0). 1단계는 웹뷰 저장소(localStorage, 빌드 불필요)+내보내기/가져오기, 다음 빌드에서 네이티브 저장(Preferences)+iCloud/Android 백업으로 올린다(7절). 서버에는 **알림을 켠 구독자의 «기기 토큰 + 종목 목록» 사본만** 둔다. 이유(실측): 아이폰 푸시는 FCM 을 거치지 않고 **APNs 직송**이다(`src/lib/push/send.ts` 주석: FCM→APNs 는 전달되지 않았다) → FCM 토픽 방식은 아이폰에서 불가. 사본 저장소는 DynamoDB(Upstash 아님 — 비용 관리 대상).
3. **우리 자원이 곧 차별점** — 이미 계산하고 있는 지표만 쓴다(새 벤더·새 비용 없음).
4. **신뢰가 먼저** — 틀린 레벨로 알림을 보내면 브랜드가 무너진다. 데이터 신뢰 게이트(8절)를 통과한 지표만 알림에 쓴다.

## 2. 우리가 가진 자원 (실측 2026-09-29 00:2x)
- 배치 API `/api/watchlist/batch?mode=price` — **5종목 1.2초(서버 0.4초·캐시)**. 종목별: 가격·등락·세션·RSI·3일 수익률·**스파크라인**·맥스페인·맥스페인 거리·GEX·풋콜·**콜월·풋플로어·감마플립**·고래 지수·**다크풀 비중**·스퀴즈 점수·IV·IV 스큐·**내재 변동폭**·VWAP·순프리미엄·블록 거래.
- `mode=full`(알파 점수·등급·근거 문장)은 3종목 3.1~3.9초 — 목록 화면엔 무겁다(상세 진입 시에만).
- 그 밖: 의회 거래·내부자 매수·실적 달력(내재 변동)·AI 종목 해설(UC)·FINRA 장외/공매도.
- 앱 하단 탭 `AppBottomNav`·구독 권유 `ValueWall`/`ProPaywall` 은 **웹 컴포넌트** → 1단계는 스토어 빌드 없이 배포 가능.
- 기존 푸시는 2종뿐(모닝 브리핑·장 마감 분석) → **종목별 알림은 새 표면**.
- ⚠ 데이터 품질(실측): 배치 API 레벨이 정의를 벗어난 종목 **5개 중 2개**(MU 풋플로어 $60·감마플립 $530·콜월이 현재가 아래, TSLA 풋플로어 200·감마플립 280). 같은 시각 구조 API 는 MU 콜월 1,100·풋플로어 900(정상). 월요일 오전 NVDA·MU 구조 값 나이 57시간(월요일 OI 미반영). → 수리 작업 칩 «Fix wrong option levels in the watchlist batch API» · HANDOFF ㊲·58.

1. **맥스페인 기반 알림은 어디에도 없다.**
2. **콜월 돌파·풋플로어 이탈·감마플립 교차를 «모바일 푸시»로 주는 곳이 없다** — 웹 전문 도구($89+)·이메일·Discord 뿐. 한국어·일본어 제품은 0.

**조사가 바꾼 판단**: 무료 5종목은 비교군 중 **가장 낮은 한도**다(TradingView 30·Stock Events 15). 경쟁사는 종목 수가 아니라 **알림(개수·속도·워치리스트 전체 알림)**을 잠근다. → 종목 수는 넉넉히, **포지셔닝 알림을 PRO 의 핵심**으로.

## 4. 화면 구성 (앱 전용 · 시안 v1 을 대표에게 제시, 9/29 00:3x)
1. **진입**: 하단 탭 `AppBottomNav` 에 «내 종목» 추가(웹 컴포넌트라 빌드 불필요) 또는 대시보드 맨 위 섹션 — 대표 결정. 권고: 탭(매일 여는 습관의 문).
2. **목록 화면**: 제목 «내 종목 · 7/10» · 정렬 칩(변화 큰 순·등락률·알림 켜짐) · 행 = 종목·이름 | 가격·등락 → **레벨 지도 막대**(풋플로어 ─ 맥스페인 표식 ─ 현재가 점 ─ 콜월) → **상태 칩 1~2개**(콜월까지 1.6% · 감마플립 위/아래 · 실적 D-2 ±8.5% · 장외 비중 급변 · 고래 신규).
3. **추가**: 종목 화면(플로우)·랭킹 행·무버 행의 ☆ 한 번 · 검색 추가. 빈 상태엔 «자주 보는 종목» 원탭(M7·SPY·QQQ) — 빈 화면을 보여 주지 않는다.
4. **행 조작**: 탭 → 그 종목 플로우 화면 · 왼쪽 밀기 → 삭제 · 길게 눌러 순서 · 🔔 → 종목 알림 설정(PRO).
5. **한도 도달**: 11번째 추가 순간 아래에서 올라오는 시트 — PRO 혜택 4줄 + «PRO 시작하기» + «코드 입력»(리딤, 다음 빌드부터 앱 안 입력).
6. **알림 설정(PRO)**: 종목별 이벤트 유형 on/off · 전체 조용한 시간 · 하루 상한 · 알림 권한 요청은 «첫 🔔 를 누를 때»(앱 시작 때 묻지 않는다).
7. **디자인 규칙**: 기존 앱과 같은 어두운 남색 바탕·카드·청록 강조 · 숫자는 고정폭 · 등락은 초록/빨강 · 레벨 지도 색은 맥스페인만 호박색 · 한/영/일 3개 언어 · 행 높이 한 화면 4~5종목.

## 6. 알림 설계
### 6-1. 이벤트(PRO) — 전부 이미 계산 중인 값, 새 벤더 없음
| 이벤트 | 판정(초안) | 데이터·주기 | 문구 예 |
|---|---|---|---|
| 콜월 돌파 | 가격이 콜월 위로 «확정»(5분 봉 종가 기준, 되돌림 방지 0.2% 여유) | 구조 서비스(단일 출처) · 장중 5~15분 | «NVDA 콜월 250 돌파 · 다음 벽 260 · 풋콜 0.97» |
| 풋플로어 이탈 | 가격이 풋플로어 아래로 확정 | 같음 | «MU 풋플로어 900 이탈 · 맥스페인 970» |

- 문구 원칙: **숫자와 사실만**(방향 예측·권유 금지 — 기존 발행 규칙과 같다). 탭하면 그 종목 «레벨 지도» 화면으로.
### 6-2. 발송 구조 (폰 저장 원칙 유지)
- 목록 원본은 폰(1단계 웹뷰 저장소 → 다음 빌드 Preferences). **알림을 켠 PRO 기기만** «기기 토큰·플랫폼·종목·유형 설정» 사본을 서버에 올린다(DynamoDB 한 표, 종목→토큰 역색인). 알림을 끄면 즉시 삭제.
- 탐지: 장중 5~15분마다 «바뀐 종목만» 이벤트 계산 → 해당 종목 구독 토큰 조회 → 기존 발송기(`src/lib/push/send.ts`: 아이폰 APNs 직송·안드로이드 FCM) 재사용.
- 억제: 같은 종목·같은 이벤트는 하루 1회 · 기기당 하루 상한 · 조용한 시간(현지 밤) · 장 마감 뒤 몰림 방지(묶음 요약).
- 비용: 쓰기·읽기 모두 «이벤트가 난 종목 × 구독 기기» 수준 — 현재 규모에선 월 몇 달러 미만(출시 후 실측으로 확인).
### 6-3. 무료 사용자
- 모닝 브리핑(기존 푸시, 문구는 모두에게 같음)을 눌러 앱을 열면 브리핑 맨 위에 **«내 종목» 요약**(가장 큰 변화 1~3개)을 **폰에서 계산해** 보여 준다 → 무료도 매일 돌아올 이유, 서버 저장 없음. (푸시 문구 자체의 개인화는 서버가 목록을 알아야 하므로 PRO 알림에서만)
