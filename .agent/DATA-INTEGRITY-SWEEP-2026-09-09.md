## 고친 것

### 1. 다크풀 분모를 «지금 상태»에서 주워 오고 있었다
실시간 스냅샷은 마감이 지날수록 «최근 체결이 있는 종목»만 남아 녹는다.
실측: **15:57 ET 13,160종목 → 20:25 ET 3,956종목.**
그래서 TSLA·AAPL·META 같은 대형주까지 분모를 못 찾아 통째로 나흘 전 값으로
이월됐다(11,757종목 중 8,058 = 69%).

→ `stock_exchanges/USCOMP/prices?date=` 로 **그 날짜를 직접 조회**한다.
  분자와 어긋날 수가 없고, 마감 당일 저녁에 확정치가 나온다.

**분모가 맞았다는 독립 증거**: 「100% 초과라 버린 행」이 2,487 → **6건**.

### 2. 재계산이 데이터를 «나쁘게» 만들 수 있었다
9/8 로 9,223종목이 저장돼 있는데 `--date=2026-09-04` 백필 한 번이 그것을
전부 9/4 로 되돌렸다. → 저장본보다 오래된 세션으로 덮어쓰지 않는다(`--force`만 허용).

### 3. 분석 캐시가 «영원히 어제 것»이었다
`cache:analysis:*` 가 전 종목 24~35시간 전 값이었다(NVDA 23.8h · META 35.1h).
TTL 3일은 「2분마다 도는 크론」을 전제로 고른 값인데 **그 크론이 없다.**
게다가 배치는 캐시가 맞으면 다시 계산하지 않는다 → **TTL 이 곧 갱신 주기.**
Intel M7·섹터·대시보드·티커 SSR 이 그 값을 오늘의 사실로 읽고 있었다.

→ 읽는 쪽에서 «어느 거래일의 값인가»로 판정(주말·휴장엔 유지)
→ `signum-warm` 이 `watchlist/batch` 를 불러 5분마다 실제로 갱신

### 4. 복원된 다크풀이 화면에 닿지 않았다
`stripDeadTickFields` 가 벤더 상실 때 굳은 값을 막으려고 읽는 입구에서
`darkPoolPct` 를 null 로 잘랐다. 그건 지금도 옳다 — 하베스터가 여전히 옛 값을
쓰기 때문이다. **그런데 자르기만 하고 넣어 주지 않았다.**
→ 잘라낸 자리에 오늘의 FINRA 값을 주입한다(Redis 키 하나·배치 1회).

### 5. 고래지수가 전 종목 «정확히 50» 이었다
범위검사(0~100)를 통과하므로 검사기로는 안 잡히고, 화면엔 «측정값처럼 보이는
상수»가 나갔다. 원인은 **계산 시점**이다 — 입력이 차기 전에 한 번 계산하고 끝냈다.
수식은 방향 입력이 0이면 활동도를 곱해도 0이라 정확히 50 을 돌려준다.
→ 세 입력이 확정되는 «응답 직전»으로 계산을 옮기고, 캐시에도 되돌려 쓴다.

### 6. netPremium «0» 이 실제 값의 주입을 막았다
`structureService` 는 프리미엄 자료가 없으면 0−0 = **0** 을 돌려준다.
AWS 보충 판정이 `Number.isFinite(0)===true` 로 «값이 있다»고 읽어 그 종목을 뺐다.
저장소에 AMZN 28,903,158 · MSFT 5,976,936 이 **있는데도** 화면엔 0 이 나갔다.

### 7. «최신 1건»이 얕으면 값이 사라진다
TSLA 실측: 21:05 레코드 12키(netPremium 없음) ← `getLatestFlow` 가 고르던 것,
20:50 레코드 14키(netPremium 359,328,823).
→ 최신을 우선하되 «빈 칸만» 직전 레코드로 채운다(같은 세션 6시간 안에서만).

### 8. 대시보드가 «호출마다» 다크풀을 줬다 안 줬다 했다
응답을 만드는 길이 둘인데 서로 다른 공급원을 봤다. 라이브 경로는
`realtimeMetricsService` 만 보고, 비면 «—» 였다. 같은 함수가 방금 받아 온
`/api/live/ticker` 안에 **이미 FINRA 값이 있었다.**
⚠️ `shortVolPct`(전체 대비)와 `darkPoolShortPct`(장외 내부 비중)는 다른 지표라 섞지 않았다.

### 9. 시장폭이 하루 밀려 있었다
`intrinio:eod:*` 는 벌크(T+1)만 봤다. 이 키는 breadth·RLSI·movers 의 단일
공급원이라 하루 밀리면 전부 밀린다.
→ 벌크가 못 준 «끝난 세션»만 거래소 EOD 로 덧붙인다.
  · 벌크가 준 날은 절대 덮지 않는다
  · 세션인지도 데이터로 판정한다(9/7 노동절 = 0종목 → 자동 제외)
  · 등락률은 직전 종가로 계산한다

## 라벨에서 «기관»을 걷어냈다

「기관 신규 포지션」은 데이터가 뒷받침하지 않는 주장이었다.
  · 주문 크기·주체를 가르는 필터가 **하나도 없다**(상위 계약 선정 기준은
    |OI증감|×2 + 거래량 — «큰손»이 아니라 «많이 움직인 계약»이다)
  · 미결제약정 증가는 산 쪽과 «쓴 쪽»이 동시에 생긴다 → 주체도 방향도 못 말한다
  · 영어는 이미 안 그러고 있었다(New Positioning) — **언어마다 다른 말**을 했다

| | 라벨 | 근거 |
|---|---|---|
| ko | **신규 포지션 구축** | 우리 UOA 설명이 이미 쓰던 말 |
| en | **New Positions** | 하루치 OI 증가엔 building 보다 정확 |
| ja | **新規建玉** | 앱 전체가 이미 建玉 로 표기 |

같이 걷어낸 것: 섹션 제목(기관이 어제 깔아둔 것 → 어제 시장이 깔아둔 것),
게이트 부제 en/ja, 그리고 **«지금 없는 카드»를 약속하던 폴백 부제**
(volatility regime · dark-pool flow — 현재 4칸에 없다).

「기관급 마켓 펄스」는 유지 — 그건 «기관이 했다»가 아니라 데이터 품질 주장이다.

# 3부 — 설정·온보딩 + UC·WIM 전수 (실사용자 흐름)

## ★ 가장 큰 것 — AI 일일 토큰 한도가 화면 두 개를 죽이고 있었다

WIM 이 「오늘은 데이터가 없어요」, UC 일본어가 「読み込めませんでした」였다.
추측을 멈추고 `?probe=1` 진단을 달아 예외를 그대로 보니:

    ThrottlingException: Too many tokens per day, please wait before trying again.

**코드 결함이 아니라 한도 소진이다.** 소비원을 계산하니:

    평일 uc-warm 80회 × (feed 3 + macro 3 + wim 1) = 하루 560회 «강제» 재생성

`refresh=1` 은 신선도를 보지 않는다 — 대부분은 아직 신선한 것을 다시 만드는 헛일이었다.

고친 것
- 워밍이 먼저 그냥 불러 신선도를 확인하고, `_stale` 일 때만 재생성한다
- UC 피드 신선도 15분 → 40분 (뉴스 «에디션»은 15분마다 다시 쓸 내용이 아니다)

| 커맨드 | 티커 캡슐을 **절대 중앙**으로 전환 | **티커 중심 오차 0px** · 헤더 44px |
| 인텔 | 커커 줄 안 (카드 유지) | 커커 28px > 배지 20px → 카드 높이 불변 |

커맨드는 예전에 좌우 버튼이 «둘 다 44px 이라 우연히» 가운데였다.
왼쪽에 무엇 하나만 얹어도 깨지는 구조였다 — 이제 폭과 무관하게 중앙이 보장된다.

### 검증 (실사용자 경로)

### ★ 실화면 검증에서 «두 번째» 버그를 잡았다 — 시세 틱이 AI 응답을 버렸다

배포 직후 첫 확인은 통과했는데, 나중에 다시 보니 **리스크 조건이 다시 하드코딩(48자)** 이었다.
API 는 200 이고 응답에 `structuralThesis`·`factorHighlights`(4건)·`repricingCondition` 이 다 있었다.
즉 **서버가 아니라 화면이 버리고 있었다.**

원인: `useEffect` 의존성에 `compositeScore`·`pcRatio`·`netWhalePremium` 같은
**시세따라 매 틱 바뀌는 값**을 넣었다.
```
시세 틱 → 의존성 변경 → 이펙트 재실행 → cleanup 이 cancelled=true
       → «날아가던 응답»을 버림 → ref 가드가 재시도 차단 → AI 가 영영 안 옴
```
**첫 확인이 통과한 것은 그 순간 시세가 안 움직였기 때문이다** — 휴장/한산할 때만 되는 버그였다.

고침(커밋 `07b87167`):
· 의존성은 «무엇을 볼 것인가»만 — `ticker · session · locale · price>0`
· 수치는 `aiPayloadRef` 로 매 렌더 갱신해 읽는다(재실행 유발 없음)
· `cancelled` 제거. 실패하면 ref 가드를 풀어 **다음 기회에 다시 부른다**

재검증(NVDA, 정규장 중 시세 움직이는 상태, 375px):
```
리스크 조건 = AI 213자 실제 리프라이싱 조건
 「(1) 상향: $230 감마 플립 돌파 시 숏감마→롱감마 전환… (2) 하향: …」
펼치기 99px ↔ 193px 정상 · 가로넘침 없음
```

**교훈: 배포 직후 한 번 통과한 것은 «통과»가 아니다.** 시장이 움직이는 상태에서
다시 봐야 한다. useEffect 의존성에 «시세»를 넣지 말 것 — ref 로 읽는다.
