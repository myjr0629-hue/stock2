## 2. 임계값 — 대표 제안 "±0.5%"를 실측으로 검증

### 결론: **0.5% 고정값은 못 쓴다.** 두 가지 이유가 각각 치명적이다.

#### 이유 ① 일간 0.5%는 «이틀에 한 번»이다 = 속보가 아니다
SPY 최근 250거래일 실측:

| 임계 | 해당 일수 | 비율 |
|---|---|---|
| ≥0.3% | 166일 | 66% |
| **≥0.5%** | **121일** | **48%** ← 이틀에 한 번 |
| ≥1.0% | 48일 | 19% |
| ≥2.0% | 5일 | 2% |

중앙값이 0.48%다. **0.5%는 평범한 하루다.**

#### 이유 ② 고정 %는 종목마다 의미가 완전히 다르다
같은 날(8/3), 30분 창에서 0.5% 이상 움직인 횟수:

| 종목 | 일간 변동성 | 30분 0.5% 발동 |
|---|---|---|
| SPY | 0.80% | **1회** |
| QQQ | 1.21% | 2회 |
| NVDA | 2.29% | 7회 |
| SOXL (3배 레버리지) | 8.24% | **12회** |

SOXL은 하루 12번 울린다. 같은 임계로 지수는 1번. **알림이 아니라 소음이다.**

### ✅ 권장: **σ 정규화 + 30분 창**

그 종목의 «1년 일간 변동성»을 30분으로 환산(√시간 규칙)한 값을 σ로 두고,
**30분 이동 ≥ 2.5σ** 를 발동 조건으로 한다.

8/3 실측 발동 횟수:

| 임계 | SPY | QQQ | NVDA | SOXL | 합계 |
|---|---|---|---|---|---|
| 1.5σ | 1 | 2 | 2 | 6 | 11 |
| 2.0σ | 1 | 1 | 2 | 1 | 5 |
| **2.5σ** | **1** | **1** | **2** | **1** | **5** |
| 3.0σ | 0 | 0 | 1 | 1 | 2 |

2.5σ가 각 종목당 **하루 1~2회**로 수렴한다. 그리고 2.5σ의 실제 %는 종목마다 다르다 —
SPY 0.56% / QQQ 0.84% / NVDA 1.59% / SOXL 5.71%. **이게 정상이다.** 각 종목의
"평소와 다름"을 같은 잣대로 잰다.

### 발동 게이트 (전부 AND)
1. 30분 이동 **≥ 2.5σ**
2. **거래량 확인** — 같은 창의 거래량이 20일 동시간대 평균의 **1.5배 이상**
   (얇은 호가로 튄 가격을 거른다)
3. **정규장 한정** (프리/애프터는 유동성이 얇아 σ가 왜곡된다)
4. **쿨다운 45분** · **하루 최대 3건** (기존 `event-detect`의 30분/3건 규약 계승)
5. 지수(SPY/QQQ)가 발동하면 **개별종목 알림은 억제** — "시장 전체"가 이미 답이다

> ⚠️ σ는 하루 한 번(장 시작 전) 계산해 캐시. 매 감지마다 1년치를 부르면 크론이 터진다.

## 3. "왜"를 붙이는 방법 — 그리고 **위험**

### 방법
움직임 발생 시각 T를 기준으로:
- `news-digest`에서 **T-45분 ~ T** 사이 발행된 뉴스를 뽑고 (이미 분 단위 타임스탬프 있음)
- 경제 캘린더에서 **T 전후 30분** 지표 발표를 뽑고
- `event-detect`의 다른 감지기(8-K, 스윕, 다크풀)가 같은 창에서 뭘 잡았는지 뽑아
- 이 셋 + 가격/거래량을 AI에 넣어 **2~3문장**을 만든다.

### ⚠️ 반드시 지킬 것 — 인과관계를 단정하지 않는다
"제조업 확장 **때문에** 나스닥이 올랐다"는 **검증 불가능한 주장**이다. 틀리면 신뢰를 잃고,
금융 콘텐츠로서도 위험하다. 병렬 서술로 쓴다:

- ❌ `제조업 확장 발표로 경기 회복력을 시사하며 나스닥 +1.11% 상승`
- ✅ `나스닥 +1.11%. 같은 시간대 ISM 제조업 확장·JPM 주택공급 투자 발표가 나왔다.`

BUFFER_OPS §0-7의 예측 프레이밍 금지와 같은 계열이다. **현재/과거 사실 + 동시성**만 쓴다.
AI 프롬프트에 이 규칙을 하드코딩하고, 기존 컴플라이언스 린트를 태운다.

### 뉴스가 없을 때
"왜"가 안 나오는 급변동이 실제로 많다(수급·옵션 만기·기계적 매매). 그때는
**"뚜렷한 촉발 뉴스 없음. 거래량 3.2배, 다크풀 58%"** 처럼 **없다는 사실 자체를 보여준다.**
이게 오히려 우리 데이터의 차별점이다 — 뉴스에 안 나오는 움직임을 설명하는 앱.

## 4. 구현안

### 4-A. 화면 (대표 요청 1번)
가디언 → OVERVIEW 탭, **모닝브리프 바로 아래**에 `BreakingCard` 삽입.
`page.tsx:576` 밑에 한 줄. 없으면 아예 렌더 안 함(자리 안 차지).

```
[🔴 속보 · 10:42 ET]                    ← 카드(접힘)
나스닥 +1.11%, S&P +1.07%
같은 시간대 ISM 제조업·JPM 발표
                              전문 보기 →
```
탭 → 모닝브리프와 **동일한 전체화면 오버레이**. 구성:
- 무엇이 움직였나 (지수/종목 + 변화율 + σ 배수)
- 같은 시간대 뉴스 3건 (출처 링크)
- 우리 데이터가 본 것 (거래량 배수 · 다크풀 · 스윕 · GEX)
- 상시 고지 문구

### 4-B. 알림 (대표 요청 3번)
```
🔴 시장 급변동
나스닥 +1.11% · S&P +1.07% — 같은 시간대 ISM 제조업 발표
```
탭 → `/{loc}/app-view/guardian?tab=overview&breaking=<id>`
→ `layout.tsx`에 `type === 'breaking'` 분기 3줄 추가 (**웹 배포**).

**필요한 개조**: `PUSH_CONTENT`가 상수 테이블이라 동적 문구를 못 넣는다.
`sendPushByType`에 `copy` 오버라이드 인자를 추가한다(기존 호출부 영향 없음).

### 4-C. 파이프라인
```
market-feed (*/2, 이미 가동)
   └→ breaking-detect (신규, */3 정규장)   ← σ 계산·게이트·쿨다운
        └→ 발동 시: 뉴스45분 + 캘린더 + 다른감지기 수집
             └→ AI 3언어 "왜" 생성 → Redis (TTL 당일)
                  ├→ 푸시 발송 (breaking, 동적 문구)
                  ├→ 가디언 BreakingCard 노출
                  └→ render-video?type=event  ← 이미 있음
```

### 4-D. 설정
알림 아코디언에 **3번째 토글 "급변동 속보"** 추가. 기본 **ON**.
`prefs`에 `breaking: boolean` 한 칸. 서버 `/api/push/preferences`는 이미 임의 키를 받는다.

## 6. 영상으로 잇기 — 그리고 대표 지적 "지표만 늘어놓지 말 것"

### 대표 지적이 맞다. 오늘 만든 샘플이 정확히 그 함정이다.
샘플 구조: `+1.01%` → `SMH/MU/AVGO` → `SOXL -3.33%` → `SOXS +3.06%` → 앱화면.
**전부 사실이지만 «왜»가 하나도 없다.** 숫자 나열이다. 보는 사람은 "그래서?"가 된다.

### 속보 = 영상의 «왜»를 공짜로 주는 소재
| 자리 | 지금 샘플 | 속보 기반 |
|---|---|---|
| 훅 | 숫자 하나 | 숫자 하나 *(유지)* |
| **긴장** | "지수는 올랐는데 반도체는 아니다" | **"왜 이 시각에 움직였나"** |
| 증거1 | 지표 3개 | **같은 시간대에 나온 것** (뉴스/지표/공시) |
| 증거2 | 콜아웃 2연타 | **우리만 아는 것** (거래량 배수·다크풀·스윕) |
| 증거3 | 앱 화면 | 앱 화면 *(유지)* |
| 페이오프 | "One tape. Two directions." | **"뉴스는 30분 뒤에 나왔다"** 류 |

즉 **VIDEO_ENGINE_SPEC §4의 서사 골격은 이미 맞다. 재료가 «지표»였던 게 문제**다.
속보 이벤트를 재료로 넣으면 같은 템플릿이 이야기가 된다.

`render-video?type=event`가 이미 있으므로 **연결만** 하면 된다.

### 영상 자동 발행은 나중
`.agent/VIDEO_ENGINE_SPEC.md §5-C` 게이트를 통과해야 하고, 아직 어떤 렌더 경로에도
게이트가 안 붙어 있다. **1~3단계 먼저, 영상은 4단계.**

## 7. 비용·리스크

**비용은 사실상 0.** 푸시는 APNs/FCM 무료. 크론은 Vercel 기존 한도 안.
AI는 하루 3~5건 × 3언어 = **15콜/일** (모닝브리프 1건보다 적다). 영상은 Lambda 편당 ~$0.02.

| 리스크 | 대응 |
|---|---|
| **알림 피로 → 앱 삭제** | 하루 3건 상한 + 쿨다운 + 기본 ON이되 1탭 해제. 초반 2주는 **하루 1건**으로 더 조인다 |

## 10. 구축하며 실측으로 잡은 것 (설계 때 몰랐던 것)

설계 문서(§2)만 보고 짰으면 전부 놓쳤을 것들이다. **다음 사람은 여기부터 읽어라.**

### 10-A. 분봉 집계가 13~15분 지연된다 ⚠️ 가장 컸다
프로덕션 실측: `17:14:24 UTC` 시점에 분봉 최신이 `17:01:00` = **13.4분 지연**.
반면 스냅샷(실시간 시세)은 `17:14:26` = **지연 0**.

> **15분 늦게 뜨는 「속보」는 속보가 아니다.**

→ 창의 **끝점만** 스냅샷으로 바꿨다. 시작점(30분 전)은 분봉 그대로 — 과거라 지연이 무관하다.
   거래량도 분봉 유지(지연돼도 «평소의 몇 배»라는 판단은 보존된다).
   수정 후 실측: 신호 시각 `13:19 ET` = 현재 ET와 일치.

같이 고친 것: 창 경계를 **봉 인덱스가 아니라 시각**(now − 30분)으로 잡는다.
인덱스로 세면 집계 지연만큼 창이 밀려 실제로는 45분 구간을 재게 된다.

### 10-B. 하루 예산이 개장 45분 만에 소진된다
8/3 전체 재현에서 발행 3건이 **14:12·14:15·14:18 — 6분 안에** 다 나갔다.
그러면 정작 대표가 중요하다고 한 **REVERSAL(15:24 GOOGL · 15:28 SOXL · 15:33 MSFT)이
전부 잘린다.** 반전은 「직전 다리」가 있어야 성립하므로 **구조적으로 장 후반에 나온다** —
선착순이면 영원히 굶는다.

→ ① 전역 간격 60분 ② SPIKE 상한 2건(나머지 1자리는 REVERSAL 몫)
   적용 후: **2건 / 72분 간격** (14:12 NVDA 5.28σ SPIKE + 15:24 GOOGL REVERSAL)

### 10-C. 프리마켓 봉을 포함하면 개장 갭이 전부 「급등」이 된다
첫 백테스트에서 후보가 22건 나왔는데, 그중 다수가 `13:31 UTC`(= 개장 1분 후)에 몰렸다.
30분 창이 프리마켓→개장 갭을 가로질렀기 때문이다. 정규장 필터를 적용하니 3건으로 줄었다.
→ `fetchRegularBars`가 09:30~16:00 ET만 남기고, `isRegularSessionNow`가 개장 15분을 더 건너뛴다.

### 10-D. Next.js route 파일은 임의 export를 금지한다
`BreakingItem`·`FEED_KEY`를 route에서 export했더니 빌드 타입 생성 단계에서 터졌다
(`tsc`만으로는 안 잡힌다 — `.next/types`가 생성돼야 보인다).
→ `services/breaking/types.ts`로 이전.

### 10-E. 검증 통로가 없으면 검증을 못 한다
실제 발동은 며칠에 한 번이라 그걸 기다려서는 카드 UI를 볼 수 없다.
그렇다고 **가짜 데이터로 검증하면 검증이 아니다 — 가짜는 언제나 예쁘게 나온다.**
→ `?preview=1&symbol=XXX` : 진짜 종목의 진짜 현재 데이터를 **같은 파이프라인**에 태우고
  σ 게이트만 건너뛴다. 숫자는 전부 실측, 다만 「알릴 만큼 크지 않은」 상태.
  `BreakingCard`는 페이지 URL에 `?preview=1`이 있을 때만 이걸 요청한다(사용자 URL엔 없다).

  ```bash
  # 화면으로 보기
  /ko/app-view/guardian?tab=overview&preview=1&symbol=SOXL
  ```

→ 그리고 **생존신호**(`detector.lastRunISO`)를 공개 필드로 뒀다. 섀도 데이터는 시크릿이
  있어야 보이지만, 「감지기가 살아 있는가」는 자격증명 없이 확인할 수 있어야 한다.

### 10-F. 문구는 언어별로 따로 써야 한다
1차 구현이 일본어를 한국어 분기에 태우고 문자열 치환으로 때웠고(`'30분'→'30分'`),
영어에 창 길이 30이 하드코딩됐으며, 어순이 「NVDA 30분 +3.35% 급등」으로 어색했다.
→ 언어별 분기로 다시 씀. 실측 확인:
- ko `NVDA 30분간 +0.25% 급등` / `SOXL 하락세 뒤집고 30분간 +1.11%`
- en `NVDA jumped +0.25% in 30 min` / `reversed higher — +1.11% in 30 min`
- ja `NVDA 30分で +0.25% 急騰` / `下落から反転、30分で +1.11%`
