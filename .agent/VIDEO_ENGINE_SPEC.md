## 0. 왜 이 문서가 있나 — 실패는 **두 겹**이었다

## 2. 레퍼런스 라이브러리

새 레퍼런스는 `node scripts/video-ref-measure.mjs <url>`로 돌리고 결과를 여기에 추가한다.

### REF-01 · 미래에셋 TIGER ETF 「60초 투자 뉴스」
**링크** https://www.youtube.com/shorts/rLlOhZ-z8ms
**정체** `알파벳 실적 발표! AI 인프라 투자에 주목해야 하는 이유` / 채널 `스마트 타이거 – TIGER ETF 공식`
**원본** 1080×1920 · 29.97fps · 63.10s · 1891프레임 · 페이스리스 · 사람 남성 내레이션

#### 2-A. ⚠️ 모델이 준 레이아웃은 틀렸다 (사고 기록)
Gemini 2패스가 **둘 다** 「상시 헤더 + 하단 1/3 불투명 다크 패널」이라고 답했고, 나는 그걸 "2패스
교차검증 일치 = 확정"으로 기록했다. **실제 프레임에는 그런 패널이 없다.**
→ **모델은 구조·타임스탬프는 잘 맞히지만 "있을 법한 레이아웃"을 지어낸다.**
→ 그래서 이 문서 최상단 규칙이 생겼다: **L1 결과는 L2 검증 전까지 기록하지 않는다.**

#### 2-B. 실제 레이어 — 풀블리드 배경 + **상단** 정렬 타이포 (패널 없음)
```
(상단)   챕터 번호 「02」 주황 + 바로 아래 주황 밑줄
         서브라인   흰색 소형   「실적의 핵심은 Google Cloud」
         헤드라인   ★주황★ 초대형 2줄 「AI 인프라 수요 증가로 / 클라우드 부문 82% 성장」
         캡션       회색 소형   「전년 동기 대비 성장세」
(중단)   차트 블록  제목 + 범례(파랑·흰색) + 축 + 라인 + 데이터 라벨
(하단)   출처·면책  2줄 소형
(최하단) 준법 스트립 「심사필 제26-0782 …」   ← 우리는 불필요
 z0      배경       풀스크린, 크게 어둡게 깔림
```
**헤드라인이 흰색이 아니라 브랜드 주황**인 게 화면을 지배한다.

#### 2-C. 컷 — 프레임 단위 확정, 전부 하드컷(블렌드 0프레임)
```
3.57  10.91  18.02  25.96  32.23  37.87 │ 49.22  51.22  53.22  58.99  (초)
└──────────── 본편 ────────────────────┘└──── 법적고지·상품 ────┘
샷 길이  3.57 / 7.34 / 7.11 / 7.94 / 6.27 / 5.64 / 11.35 │ 2.00 / 2.00 / 5.77 / 4.11
```
컷은 음악이 아니라 **내레이션 문장 시작**에 붙는다.

#### 2-D. 배경 — **샷마다 기법이 다르다** (표본 하나로 일반화 금지)
프레임간 차는 거의 0인데 «샷 처음↔끝» 누적차가 크다 = 아주 느린 연속 이동.

| 샷 | 프레임간 | 누적 | 확대 정합 | 이동 정합 | 판정 |
|---|---|---|---|---|---|
| 3.57–10.91 (피차이 실사) | 0.24 | 20.96 | k=1.01 개선없음 | **dx=−7, 36.5→8.8** | **수평 팬** → 정지 이미지+translate로 재현 **가능** |
| 10.91–18.02 (AI칩 3D) | 0.90 | 25.20 | k=1.000 개선 0 | dx=0 dy=0 개선 −0.00 | **내부 애니메이션** → 정지+CSS **불가** |
| 25.96–32.23 | 2.08 | 34.65 | — | — | 내부 애니메이션 계열 |
| 37.87–49.22 | 1.07 | 39.91 | — | — | 내부 애니메이션 계열 |
| 49.22–53.22 (고지 카드) | 0.00 | 0.01 | — | — | 완전 정지 |

> 나는 처음에 AI칩 샷 하나만 보고 "배경은 전부 내부 애니메이션"이라 단정했다. 측정 스크립트를 만들어
> **전 샷을 돌리자 실사 샷에서 팬이 잡혔다.** → 배경 조달 비용이 추정보다 작다(§7 반영).

#### 2-E. 텍스트 진입 — 컷 후 **750ms 대기 → 600ms 진입 → 정지**
컷 직후 14프레임(0~0.43s) 변화 0 = 아직 없음. 0.75s 급상승 → 0.9~1.1s 최대 → 1.4s 종료.
방식은 **마스크 와이프**(1.0s 프레임에서 글자가 세로로 잘린 채 드러남). 이후 드리프트 없음.

#### 2-F. 차트 — **왼→오 리빌 와이프, 블록 전체를 한 장의 마스크로**
컷 후 **약 1.2s 시작, 약 800ms**(1.6s에 약 45%, 2.6s에 완성 — 프레임 실사).
1.6s 프레임에서 범례가 **글자 중간에서 잘려** 있고 X축 라벨이 오른쪽으로 갈수록 사라지며 라인도
좌측만 그려져 있다. 제목·범례·축·라인·데이터라벨이 **개별 애니메이션이 아니라 통째로** 쓸려 나온다.
→ 리모션 `clip-path: inset(0 X% 0 0)` 하나로 정확히 재현. **가장 싸고 효과 큰 기법.**

#### 2-G. 기타
가라오케 자막 **없음**. 샷당 헤드라인 1블록.
64초 중 약 15초(23%)가 법적 고지 → **우리는 이 구간이 통째로 비고 그 자리에 앱 CTA가 들어간다.**

## 3. 제작 스펙

| 항목 | 값 |
|---|---|
| 총 길이 | **32초** = 콘텐츠 26 + 아웃트로 6 |
| 종횡비 | 9:16 · 1080×1920 · 30fps |
| 오디오 | **무음** |
| 자막 속도 | **13 CPS** |
| 언어 | **영어 우선** |
| 발행 | 하루 3편 + 앱 전용 1편 |

### 3-A. 왜 32초인가
- **위 제약** — 바이럴 스위트스팟 24–38초. 완주율이 알고리즘 최상위 신호. 콜드스타트에선 길수록 불리.
- **아래 제약** — 아웃트로는 콘텐츠가 아니라 **완주율을 깎는 구간.** 6초가 20%를 넘지 않으려면 총
  30초 이상. 25초+6초면 이탈 시 76%, 32초면 81%.
- 교집합 30–38초 → **32초**.
- 참고: 전 카테고리 기준 50~60초가 조회 최다지만 그건 **팔로워 있는 채널** 기준.
  **승자 훅이 나오면 그 클립만 50~60초 확장판을 테스트**한다.

### 3-B. 자막 13 CPS — 레퍼런스 속도를 그대로 베끼면 안 되는 이유
레퍼런스는 **사람 내레이션 + 헤드라인 블록**이라 텍스트를 안 읽어도 전달된다.
**우리는 무음 → 못 읽으면 그 정보는 사라진다.** 가져올 것은 *속도*가 아니라
**"샷당 한 블록, 진입 후 고정"이라는 규율**이다.
- 업계 표준 17 CPS, **20 CPS 초과 시 대부분 다 못 읽음**
- 단 표준은 *소리를 들으면서* 읽는 전제. 우리 시청자는 **텍스트 + 숫자/차트를 동시에** 본다
- → **13 CPS.** 표준 대비 23% 낮춘 여유분이 곧 그래픽 흡수 시간

### 3-C. 텍스트 2단 티어 — 3초컷과 무음 자막은 양립 불가
3초 × 13 CPS = 34자. 영어 헤드라인 한 문장이 안 들어간다. 컷을 늘리는 대신 텍스트를 나눈다.

| 티어 | 예시 | 글자수 | 샷 길이 |
|---|---|---|---|
| **헤드라인**(문장) | `Dark pools absorbed 51% of NVDA volume today` | 44자 | 4–5초 |
| **콜아웃**(숫자+라벨) | `51% DARK POOL` | 13자 | 2.5–3초 |

교차 배치 → 평균 3.7초. 읽기도 되고 완급도 산다.

### 3-D. 아웃트로 — 3앱 동시 금지, **1앱 로테이션**
6초에 3앱을 넣으면 앱당 2초 = 로고 나열이지 광고가 아니다.
**영상 1편 = 앱 1개.** 하루 3편이니 SIGNUM / UC / WIM이 하루 한 번씩 다 나간다. 노출 총량 동일,

#### 5-C-2. 🔢 «영상 안에 숫자는 한 소스에서만 온다»
샘플 1차는 자막 `Price $107.55` + 앱 캡처 `$116.93` = **한 영상에 가격이 두 개**였다.

시세는 초 단위로 움직이므로 «캡처 시점»과 «대본 시점»을 맞추는 건 근본적으로 경주다.
→ **자막은 라벨만 말하고 숫자는 화면이 말하게 둔다.**

  경주 자체가 사라지고, 덤으로 «이 앱에서 뭘 볼 수 있는지»를 말하게 되어 광고로서도 낫다.

### 5-D. 🔁 이식성 규칙 — 로컬에서 만들되 **AWS로 그대로 올라가게**

Remotion은 **같은 컴포지션을 로컬(`renderMedia`)과 람다(`renderMediaOnLambda`)가 동일하게 렌더**한다.
React 코드·타이밍·레이아웃은 한 줄도 안 바뀐다. **깨지는 건 코드가 아니라 «환경 의존»이다.**
현재 레포 실측으로 확인된 지뢰 3개와 그 규칙:

| 지뢰 (실측) | 규칙 |
|---|---|
| `fontFamily: 'Inter'` ×20, `'Montserrat'` ×1 — **이름만 부르고 어디서도 로드 안 함.** `@remotion/google-fonts`는 **설치만 되고 사용처 0곳** | **폰트는 `@remotion/google-fonts`로 명시 로드만.** 시스템 폰트 의존 금지. 맥엔 Inter가 있어 로컬은 보이지만 렌더 환경에 없으면 글자가 안 그려진다 — **실패 ②의 유력 원인** |
| `staticFile()` 352회(audio) + 36회(broll), `public/shorts` 25MB | **큰 소재(배경 영상·앱 녹화)는 HTTPS URL 참조.** `staticFile()`은 로고·아이콘 등 작은 것만. 람다는 site 번들에 들어간 것만 읽는다 |
| 로컬 녹화 MP4는 람다가 못 읽음 | 캡처 결과를 **처음부터 URL로 올려두고 URL을 넘긴다** |

→ **소재 베이스를 env 하나로:** `ASSET_BASE` (로컬 `http://localhost:3000`, 람다 `S3/CDN`).
이 3개만 지키면 이전은 **「env 바꾸고 `scripts/deploy-remotion-lambda.mjs` 실행」으로 끝난다.**
지키지 않으면 나중에 전면 재작업이다.

⚠️ 정직하게: **검정 영상의 원인을 폰트로 «단정»하지 않았다.** 폰트 미로드가 가장 유력하지만 확정하려면
그 컴포지션을 다시 렌더해봐야 한다. 신규 라인은 어차피 폐기 결정이라 **원인 규명보다 규칙으로 막는
게 실익이 크다.**

### 5-E. 🖥 로컬 통제 콘솔 (대표 확정 요구사항)

*"영상생성을 로컬에서 하더라도 로컬 웹 페이지를 만들어서 작동 상태를 직접 보면서 했으면 한다."*

#### 이미 쓸 수 있는 것 — Remotion Studio
```bash
npm run remotion:studio      # = npx remotion studio src/remotion/index.ts
```
컴포지션 목록·타임라인 스크럽·프레임 이동·props 실시간 편집·저장 시 즉시 반영.
**템플릿을 만들며 눈으로 보기엔 이게 최적이고 추가 개발이 0이다.**
단 이건 **제작 도구**지 운영 콘솔이 아니다 — "오늘 3편이 어디까지 갔나"는 못 본다.

#### 만들 것 — `/admin/video`
바닥이 이미 있다: `src/app/[locale]/admin/` 아래 콘솔 5개(marketing·health·content-center·
og-audit·trade)가 돌고, `ADMIN_EMAILS` 인증 패턴도 있다. **같은 자리에 하나 더 얹는다.**

| 영역 | 보여줄 것 |
|---|---|
| 오늘의 3편 | 슬롯별 상태 — 데이터 ✅ → 대본 ✅ → 렌더 ⏳63% → 검수 → 대기 |
| 진행률 | Remotion `onProgress`를 **SSE로 스트리밍** → 실시간 프레임 카운터 |
| **검수 결과** | 평균밝기 / 밝은화소 / 컷 수 + **PASS·FAIL** (§5-C) |
| 미리보기 | 렌더된 MP4 그 자리에서 재생 |
| 대본 | 샷별 텍스트 + **글자수/CPS 초과 경고**(§3-C·3-E) |
| 소재 | 이번 편에 쓰인 배경·앱 화면 썸네일 |
| 버튼 | 재렌더 · 대본 수정 · **승인** · 발행 |
| 로그 | 실패 원인(폰트 미로드·에셋 404 등) |

**핵심은 검수 칸이다.** 검정 영상이 대표에게 도달한 건 이 화면이 없어서다.
`❌ 평균밝기 5.2 < 25`가 빨갛게 떴으면 끝날 일이었다.

```
브라우저 /admin/video
    ↕ SSE (진행률·로그 실시간)
로컬 Next 개발서버
    ├ 데이터 수집 → 기존 flow/intel 엔드포인트
    ├ 대본 생성   → 기존 AI 캡션 엔진
    ├ 렌더        → @remotion/renderer (로컬)
    ├ 검수        → video-ref-measure.mjs 의 GATE
    └ 발행 큐     → 승인된 것만
```

⚠️ **같은 레포라 그냥 만들면 Vercel에 함께 배포된다.** 운영 콘솔이 공개되면 안 된다.
→ **처음부터 `ADMIN_EMAILS` 인증을 넣고, 렌더 실행만 로컬 여부를 체크**한다.
(로컬 전용 404로 막는 방법도 있으나, 나중에 람다로 옮기면 인증이 어차피 필요해진다.)

## 7. 배경 소재 조달 — **미결, 대표 결정 필요**

§2-D로 전제가 두 번 바뀌었다. 현재 판단은 이렇다.

| 안 | 비용 | 자동화 | 차별성 |
|---|---|---|---|
| **A. 스톡 영상 라이브러리** 20~40클립 확보 후 재사용 | 1회 or 저가 | 완전 | 중 (남들도 씀) |
| **B. Higgsfield/Veo로 30~50클립 1회 대량 생성** 후 재사용 | 1회 $150~500 | 생성만 수동 | 상, 브랜드 전용 |
| **C. 우리 앱 화면·데이터 그래픽 자체를 배경으로** | **$0** | **완전** | **최고** |

**권고: C 기본 + B 1회성 보조.**
우리 해자는 시네마틱 b-roll이 아니라 **아무도 못 보는 데이터**다. 배경을 "우리 터미널이 살아 움직이는
화면"으로 잡으면 비용 0·자동화 완전·차별성 최고. 시네마틱이 꼭 필요한 훅 2~3초만 B로 **한 번에 몰아
생성**해 라이브러리화한다(월 구독 아님).
**§2-D 발견으로 부담이 더 줄었다** — 실사 계열은 정지 이미지 + 팬으로 충분하고, 진짜 움직이는 영상이
필요한 건 3D 렌더 계열뿐이다.

### Higgsfield 현황
공식 MCP `mcp.higgsfield.ai/mcp`, API 키 불필요, Kling 3·Veo 3·Sora 2 등 30+ 모델, 편당 $3–12
(Ultra ~$99/mo). 상세 비교 `SHORTS_STRATEGY.md` §1.
**상시 사용 보류 사유 (여전히 유효):**
1. 비용 — 3편/일 × 30일이면 월 $270–1,080
2. **자동화 불가** — 호스티드 MCP는 대화형 인증이라 헤드리스 cron에 못 붙는다
3. 상업 라이선스 ToS 미확인
→ 따라서 **상시 파이프라인 아님. "1회 대량 생성 후 라이브러리화"로만** 쓴다.

## 8. 도구 — 레퍼런스 분석 엔진 (2단 고정)

| 층 | 도구 | 답하는 질문 | 신뢰도 |

```bash
node scripts/video-ref-measure.mjs "https://www.youtube.com/shorts/..."   # 레퍼런스
node scripts/video-ref-measure.mjs out/our_render.mp4                     # 자가검수
```

**L2가 하는 6가지:** ①컷 프레임 확정 ②샷별 «프레임간 vs 누적» 배경 이동 ③켄번즈·팬 정합으로 이동
종류 판정 ④영역 분할 진입 타임라인 ⑤리빌 엣지 추적 ⑥활력 지표(§5-C 게이트)

**설치 상태 (2026-07-31 확인)**
- `~/.local/bin/yt-dlp_macos` — 단독 바이너리 2026.07.04. **시스템 파이썬 3.9와 무관.**
  (pip 설치본은 3.9 제약으로 2025.10까지 → 유튜브를 못 연다. 최신은 Python 3.10+ 요구)
- 리모션 번들 ffmpeg `node_modules/@remotion/compositor-darwin-arm64` (n7.1).
  **`DYLD_LIBRARY_PATH`를 같은 폴더로** 잡아야 실행됨. **최소 빌드라 필터 50개뿐** —
  `scdet/ssim/psnr/select/showinfo` 없고 `rawvideo` 먹서도 없다 →
  `-c:v rawvideo -f image2pipe`로 덤프해 **Node에서 계산**.
- `gemini-2.5-pro`는 무료 티어 할당량 0 → flash만 사용.
- `guimatheus92/mcp-video-analyzer`(URL→전사·키프레임·OCR·`get_frame_burst`)는 **미설치**.
  L2가 프레임을 직접 재므로 급하지 않다. 대본·OCR이 필요해지면 그때.

| **1** | **검수 게이트 배선 + 콘솔 껍데기**(`/admin/video`, SSE 진행률, 검수 표시) | 실패 ② 재발 방지가 최우선. 이후 전 작업의 눈이 된다 |

| **4** | **대본 생성기** — 기존 AI 캡션 엔진에 §3-E 슬롯 채우기 + 글자수 검증 | |

| **6** | 배경 소재 라이브러리 구축(§7 결정 후) | |
