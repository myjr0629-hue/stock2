## 1. 레퍼런스

**링크:** https://www.youtube.com/shorts/rLlOhZ-z8ms
**정체:** 미래에셋자산운용 TIGER ETF 광고. 64초. 페이스리스. **사람 남성 내레이션.** 포맷명 「60초 투자 뉴스」.
**참고 대상:** 내용이 아니라 **그래픽 UI·흐름 틀·속도·이미지 사용법**(대표 명시).

### ✅ 실측 확정 (2026-07-31 — 원본 다운로드 + 전 프레임 수치 분석)

원본 `1080×1920 · 29.97fps · 63.10s · 1891프레임`. 제목 `알파벳 실적 발표! AI 인프라 투자에
주목해야 하는 이유` / 채널 `스마트 타이거 – TIGER ETF 공식`. **아래는 추정이 아니라 측정값.**

#### ⚠️ Gemini가 준 "레이어 모델"은 틀렸다 — 폐기
Gemini 2패스가 **둘 다** 「상시 헤더 + 하단 1/3 불투명 다크 패널」이라고 했으나 **그런 패널은 없다.**
실제 프레임은 풀블리드 배경 위에 콘텐츠가 직접 얹히고 **텍스트는 상단**이다.
→ 교훈: 모델은 구조·타임스탬프는 잘 맞히지만 **"있을 법한 레이아웃"을 지어낸다.** 레이아웃도
프레임을 봐야 한다.

**실제 레이어 — 풀블리드 배경 + 상단 정렬 타이포 (패널 없음)**
```
(상단)   챕터 번호 「02」 주황 + 바로 아래 주황 밑줄
         서브라인   흰색 소형   「실적의 핵심은 Google Cloud」
         헤드라인   ★주황★ 초대형 2줄 「AI 인프라 수요 증가로 / 클라우드 부문 82% 성장」
         캡션       회색 소형   「전년 동기 대비 성장세」
(중단)   차트 블록  제목 + 범례(파랑·흰색) + 축 + 라인 + 데이터 라벨
(하단)   출처·면책  2줄 소형
(최하단) 준법 스트립 「심사필 제26-0782 …」  ← 우리는 불필요
 z0      배경       풀스크린, 크게 어둡게 깔림
```
헤드라인이 흰색이 아니라 **브랜드 주황**인 게 화면을 지배한다.

#### 컷 — 프레임 단위 확정
```
3.57  10.91  18.02  25.96  32.23  37.87 │ 49.22  51.22  53.22  58.99  (초)
└──────────── 본편 ────────────────────┘└──── 법적고지·상품 ────┘
샷 길이  3.57 / 7.34 / 7.11 / 7.94 / 6.27 / 5.64 / 11.35 │ 2.00 / 2.00 / 5.77 / 4.11
```
전부 하드컷(블렌드 0프레임).

#### 배경은 **움직인다** — 단 줌도 팬도 아니다
| 샷 | 프레임간 평균차 | 샷 처음↔끝 누적차 |
|---|---|---|
| 3.57–10.91 | 0.24 | **20.96** |
| 10.91–18.02 | 0.90 | **25.20** |
| 25.96–32.23 | 2.08 | **34.65** |
| 37.87–49.22 | 1.07 | **39.91** |

프레임간은 거의 0인데 누적차가 크다 = **아주 느린 연속 이동**. 정지 이미지면 누적차도 0이어야 한다.
**★ 샷마다 기법이 다르다** (2026-07-31 `scripts/video-ref-measure.mjs`로 재확인)

| 샷 | 확대 정합 | 이동 정합 | 판정 |
|---|---|---|---|
| **3.57–10.91** (피차이 실사) | k=1.01, 개선 없음 | **dx=−7 · 오차 36.5→8.8** | **수평 팬** — 정지 이미지 + translate로 재현 **가능** |
| **10.91–18.02** (AI칩 3D) | k=1.000, 개선 0 | dx=0 dy=0, 개선 −0.00 | **내부 애니메이션** — 정지+CSS로 재현 **불가** |
| 49.22–53.22 (법적고지 카드) | — | 프레임간 0.00 / 누적 0.01 | 완전 정지 |

→ **하나로 뭉뚱그리면 안 된다.** 실사 소재는 팬으로 살리고(정지 이미지로 충분), **3D 렌더 소재만
실제 움직이는 영상이 필요하다.** 배경 조달 비용이 생각보다 작다는 뜻이다 — §9 재검토에 반영.

> 첫 판에서 나는 AI칩 샷 하나만 보고 "배경은 전부 내부 애니메이션"이라 단정했다. 측정 스크립트를
> 만들어 전 샷을 돌리자 실사 샷에서 팬이 잡혔다. **표본 하나로 일반화하지 말 것.**
⚠️ **이 사실이 §6(Higgsfield 보류) 판단의 전제를 바꾼다.** 그 판단은 "배경은 정지 이미지"라는
틀린 전제 위에 있었다 — 재검토 필요.

#### 텍스트 진입 — 컷 후 **750ms 대기 → 600ms 진입 → 정지**
컷 직후 14프레임(0~0.43s) 변화 0 = 아직 텍스트 없음. 0.75s 급상승 → 0.9~1.1s 최대 → 1.4s 종료.
방식은 **마스크 와이프**(1.0s 프레임에서 글자가 세로로 잘린 채 드러남). 이후 드리프트 없음.

#### 차트 — **왼→오 리빌 와이프, 블록 전체를 하나의 마스크로**
컷 후 **약 1.2s 시작, 약 800ms**(1.6s에 약 45%, 2.6s에 완성 — 프레임 실사).
1.6s 프레임에서 범례가 **글자 중간에서 잘려** 있고 X축 라벨이 오른쪽으로 갈수록 사라지며 라인도
좌측만 그려져 있다. **제목·범례·축·라인·데이터라벨이 개별 애니메이션이 아니라 한 장의 마스크로
통째로 쓸려 나온다.**
→ 리모션에서 `clip-path: inset(0 X% 0 0)` 하나로 정확히 재현. **가장 싸고 효과 큰 기법.**

#### 기타
가라오케 자막 **없음**. 샷당 헤드라인 1블록. 내레이션은 사람 목소리.
64초 중 약 15초(23%)가 법적 고지 → **우리는 이 구간이 통째로 비고 그 자리에 앱 CTA가 들어간다.**

   yt-dlp는 3.9 제약으로 2025.10 버전까지만 되고 유튜브를 못 연다).

| 항목 | 값 | 근거 |
|---|---|---|
| **총 길이** | **32초** = 콘텐츠 26 + 아웃트로 6 | 아래 §2-A |
| **오디오** | **무음** (내레이션·TTS 없음) | 쇼츠 무음 시청 비중 |
| **자막 속도** | **13 CPS** | 아래 §2-B |
| **언어** | **영어 우선**, ko/ja는 후속 | 대표 결정 |

| 종횡비 | 9:16 · 1080×1920 · 30fps | |
| 발행 | 하루 3편 + 앱 전용 1편 | |

### 2-A. 왜 32초인가
- **위 제약:** 바이럴 스위트스팟 24–38초. 완주율이 알고리즘 최상위 신호. 콜드스타트(팔로워 0)에선
  길수록 불리.
- **아래 제약:** 아웃트로는 콘텐츠가 아니라 **완주율을 깎는 구간.** 6초 아웃트로가 전체 20%를 넘지
  않으려면 총 30초 이상이어야 한다. 25초에 6초를 붙이면 이탈 시 76%, 32초면 81%.
- **교집합 = 30–38초 → 32초 확정.**

### 2-B. 자막 13 CPS — 레퍼런스를 그대로 베끼면 안 되는 이유
레퍼런스는 **사람 내레이션 + 헤드라인 블록**이다. 텍스트는 음성의 보조라 안 읽어도 전달된다.
그래서 7초 샷에 3초면 읽을 텍스트를 여유롭게 걸었다.

**우리는 무음 → 못 읽으면 그 정보는 사라진다.** 가져올 것은 *속도*가 아니라
**"샷당 한 블록, 진입 후 고정"이라는 규율**이다.

- 업계 표준: 일반 시청자 **17 CPS**, **20 CPS 초과 시 대부분 다 못 읽음**.
- 단 표준은 *소리를 들으면서* 읽는 전제. 우리 시청자는 **텍스트 + 숫자/차트를 동시에** 봐야 한다.
- → **13 CPS.** 표준 대비 23% 낮춘 여유분이 곧 그래픽 흡수 시간.

### 2-C. 텍스트 2단 티어 — 3초컷과 무음 자막은 양립 불가
3초 × 13 CPS = 34자. 영어 헤드라인 한 문장이 안 들어간다. 컷을 늘리는 대신 텍스트를 나눈다.

| 티어 | 예시 | 글자수 | 샷 길이 |
|---|---|---|---|
| **헤드라인**(문장) | `Dark pools absorbed 51% of NVDA volume today` | 44자 | 4–5초 |
| **콜아웃**(숫자+라벨) | `51% DARK POOL` | 13자 | 2.5–3초 |

교차 배치 → 평균 3.7초. 읽기도 되고 완급도 산다.

### 2-D. 아웃트로 — 3앱 동시 금지, 1앱 로테이션
6초에 3앱을 넣으면 앱당 2초 = 로고 나열이지 광고가 아니다. 실앱 화면 자리가 안 나온다.

**영상 1편 = 앱 1개.** 하루 3편이니 SIGNUM / UC / WIM이 하루 한 번씩 다 나간다. 노출 총량 동일,
앱당 6초를 온전히 사용(디바이스 프레임 + 실제 작동 화면 + 이름 + Free).

**부가 효과:** `SHORTS_STRATEGY.md` §5의 **중복 콘텐츠·스팸 신호 위험이 자동 해소**된다. 매일 3번
픽셀 동일한 엔딩이 아니라 3종 로테이션. **앱당 2종씩 총 6개**를 한 번 고퀄로 제작해두면 변주까지 확보.

⚠️ **아웃트로를 별도 MP4로 만들어 ffmpeg concat 하지 말 것.** 리모션 컴포지션의 마지막
`<Series.Sequence>`로 둘 것 — 인코딩 1회, 앱 아이콘·카피·버전이 코드 한 곳에서 바뀐다.

### 2-E. 샷 플랜 (32초 기준, 13 CPS · 진입 0.4초 차감 후 실측 예산)
```

0:03–0:07  긴장      헤드라인                     ≤47자
0:07–0:12  증거1     헤드라인 + 차트              ≤60자

0:15–0:18  증거2b    콜아웃                       ≤20자
0:18–0:23  증거3     실앱 화면(디바이스 프레임)   ≤60자
0:23–0:26  페이오프  헤드라인                     ≤34자
──────────────────────────────────────────────────
```

컷 7회 전부 하드컷. 콘텐츠 평균 3.7초. **글자수 초과 시 렌더 실패하도록 검증 걸 것.**

### 2-F. ⚠️ 다국어 — 지금 구조에 넣지 않으면 나중에 못 넣는다
영어 13 CPS · 5초 = 60자. **같은 5초에 일본어는 약 20자**(한자 밀도), 한국어는 영어의 절반 수준.
영어로만 컷 길이를 고정하면 3언어 확장 시 번역이 안 들어가거나 전 템플릿 재작업이 된다.

→ **`durationInFrames`를 글자수에서 산출하는 구조로 처음부터 짤 것.** 리모션은 코드라 언어별 샷
길이를 다르게 계산하는 게 공짜다.

| **B —「데이터 리빌」** | 15–20초 | 훅 실험용. 크롬 없음, 1프레임 큰 숫자 |

**레퍼런스에서 가져오는 것:** 고정 크롬 + 교체 배경 / 하드컷 온리 / 챕터 번호 / 샷당 텍스트 1블록.
**안 가져오는 것:** 7초 템포(우리는 3.7초) / 준법 스트립 / 상품 카드 엔딩.

## 6. Higgsfield — 지금은 붙이지 않는다 (2026-07-30 판단)

공식 MCP `mcp.higgsfield.ai/mcp`, API 키 불필요, Kling 3 · Veo 3 · Sora 2 등 30+ 모델, 편당 $3–12
(Ultra ~$99/mo). 상세 비교는 `SHORTS_STRATEGY.md` §1.

**보류 사유 3:**
1. **비용** — 리모션 $0.02 대비 150–600배. 3편/일 × 30일에 b-roll을 얹으면 월 $270–1,080.
   설치 0건인 UC를 안고 있는 지금 쓸 곳이 아니다.
2. **자동화 불가** — 호스티드 MCP는 **계정 대화형 인증**이라 헤드리스 cron에 못 붙는다. 데일리
   파이프라인에 넣을 수 없고 수동 배치가 된다. [[prioritize-automated-over-manual-grind-marketing]] 위배.
3. **상업 라이선스 미확인** — `SHORTS_STRATEGY.md` §7 숙제 그대로. 광고 영상에 쓰려면 ToS 먼저.

**대신:** 리모션으로 3편/일을 돌려 48시간 훅 판정 데이터를 쌓고, **승자 클립에만** 주 1–2회 시네마틱
훅샷 2–3초를 얹는다. 그때 무료 크레딧으로 Higgsfield vs Flow/Veo 실비교 후 하나만 고른다.
