## 1. 하루 3편 편성 — 확정

### ⛔ 기존 편성(08:00 / 14:00 / **22:00**)은 폐기한다

`22:00 KST = ET 09:00` 은 **실측상 최악 구간**이다 — 채널내 z **−0.15**, n=578, 99% 유의.
우리가 지금까지 가장 많이 쓰던 시간이 가장 나쁜 시간이었다.

### 확정 슬롯

| 시각(KST) | = ET | 실측 | 트랙 | 성격 |
|---|---|---|---|---|
| **13:00** | 00:00 | **d +0.31 ★★** | **CLOSE** | 전일 미국 마감 해석 (마감은 KST 05:00) |
| **16:00** | 03:00 | **d +0.31 ★★** | **CONCEPT** | 개념 설명 — 시의성 없음, 재고에서 꺼냄 |
| **19:30** | 06:30 | d −0.03 (중립) | **MORNING** | 미국 프리마켓 — 내용상 이 시간이어야 한다 |

- 두 편은 **실측 최적 구간**에 넣고, 프리마켓 브리핑만 내용 때문에 중립 구간에 둔다
- **KST 22:00~01:00 에는 절대 올리지 않는다** (d −0.15, 99% 유의)
- 성격이 겹치면 하나를 버린다. 같은 티커·같은 각도 두 편 금지
- 2주에 1회, 16:00 자리에 **앱 광고** 변형본을 넣는다

### 소재 병목

하루 3편 = 주 21편. **개념편 재고 15편을 먼저 쌓는다.** 재고 없이 시작하면 품질이 무너진다.
현재 재고 1편(C1 Max Pain). 개념 8종 목록은 `CONCEPT_TRACK.md §2`.

## 3. 메타데이터 규격 — 쇼츠 2,144편 실측에서 확정

### 결론: 제목·태그·설명의 «형식»은 조회수를 가르지 않는다

상위 536편(조회 중앙 4,253)과 하위 536편(478)은 **8.9배** 차이인데, 이를 가르는
메타데이터 특징이 **하나도 없다.** 전 항목 |r| ≤ 0.06, 보유율 차이 ≤ 5%p.
존재 증명: 1,571만 영상은 **태그 0개 · 설명 0자**.

### 그래서 제목은 «검색»만 노린다

| # | 규칙 | 근거 |
|---|---|---|
| 1 | 실제 검색 수요가 있는 문구를 **앞쪽에** | `options expire worthless` 2,822 vs `max pain options trading` 65 — **43배** |
| 2 | **동음이의어 충돌을 확인한다** | `max pain` 검색 1위가 게임 «Max Payne» 530만 |
| 3 | 물음표·이모지·전부대문자·2인칭은 **효과 없다.** 넣을 이유가 없으면 넣지 않는다 | n=1,964 전부 무의미 |
| 4 | 태그 10~15개, 실제 검색되는 말만. 스터핑 금지 | 태그 개수 상관 **−0.01** |
| 5 | 설명은 «검색문장 + 앱주소 + 면책»만 | 설명 글자수 상관 0.01 |
| 6 | 해시태그 1~3개 | 상관 0.01 |
| 7 | **제목 또는 설명에 FREE 를 반드시 넣는다** | 대표 지시. 업로더가 없으면 거부한다 |

### ⛔ 폐기된 제목 공식

「고유명 +21 · how +9 · you/your −6」은 **채널 구분 없이** 상하위를 비교한 결과였다.
「어느 채널이냐」가 「제목 효과」로 둔갑한 것이다. 채널 내부 비교로 다시 재니 전부 사라졌다.

## 4. 업로드 절차 — 내가 올린다, 개시는 대표가 한다

```bash
node scripts/yt-upload.mjs .agent/plans/YYYY-MM-DD.json --dry   # 규약 검증
node scripts/yt-upload.mjs .agent/plans/YYYY-MM-DD.json          # 실제 업로드
```

- **항상 `privacyStatus: private` + `publishAt` 예약**으로 올린다. 공개 전환은 대표가 한다
- 업로더가 **올리기 전에 규약 위반을 거부**한다:
  파일 존재 · 제목 100자 · 설명에 앱주소 · **FREE 존재** · 예약시각이 KST 22~01시가 아닐 것 · 썸네일 존재
- 기록은 `.agent/PUBLISH_LOG.md` 에 자동 추가

### ⛔ 업로드 체크리스트

- [ ] **자막 파일(SRT)을 올리지 않는다** — 번인 자막이 있어 이중 자막이 된다
- [ ] **썸네일은 본편 프레임 캡처** — 따로 만들지 않는다
- [ ] 고정 댓글에 **앱 주소** 포함
- [ ] AI 사용 신고: 배경 플레이트가 Flow 생성물이면 **「예」**
- [ ] 세로 1080×1920 · 60초 미만

## 5. Gemini 의견 — 무엇이 틀렸고 무엇을 배웠나

대표가 외부 모델(Gemini)에 마지막 영상 분석을 맡겨 받은 의견이다. **주장 두 개는 실측으로 기각됐다.**

| Gemini 주장 | 실측 | 판정 |
|---|---|---|
| 「엔드카드가 루프를 죽인다」 | 지속 곡선이 끝에서 **1.15** (>1.0 = 되감아 본다) | **기각** |
| 「16초로 압축해라」 | 길이 ↔ 지속률 **−0.08** — 관계 없음 | **기각** |

### 그래도 배운 것 — 「주장」이 아니라 「질문」이 쓸모 있었다

1. **엔드카드 산술을 하게 만들었다.** 기각하는 과정에서 «뒤에 뭘 붙이면 조회율이 얼마나
   깎이는지»를 계산했고 (60% → 45.6% → 27.8%), 그 결과 «앱 광고를 본편에 붙이지 않는다»가
   확정됐다. 주장은 틀렸지만 그 덕에 규칙 하나가 근거를 얻었다.
2. **CTA 2.77초의 «질»을 보게 만들었다.** 길이를 못 줄이면 밀도를 올려야 한다 →
   CTA 를 폰 목업 + 지표 칩으로 교체. **길이 비용 0.**
3. **외부 의견은 «가설 공급원»으로만 쓴다.** 채택 기준은 언제나 실측이다.
   이건 Gemini 가 「하단 1/3 불투명 패널」을 두 번 지어냈던 사고와 같은 교훈이다
   (`VIDEO_ENGINE_SPEC.md` §2-A).

### 승격 규칙

1. **표본 30편 미만에서는 새 규칙을 만들지 않는다**
2. **상관 |0.5| 미만 / 보유율 차이 20%p 미만은 규칙으로 승격하지 않는다**
3. 효과가 있어 보이면 **순열검정**으로 «우연히 나올 수 있는 크기»인지 먼저 가른다
4. 교차채널 비교로 결론내지 않는다 — **반드시 채널 내부 z** 로 본다
