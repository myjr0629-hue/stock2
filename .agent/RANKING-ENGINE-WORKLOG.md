## ★ 「준비 상태(readiness)」 — 앞으로 만들 랭킹의 기반

자료가 아직 안 쌓인 랭킹을 위한 구조다. 랭킹이 필요한 것을 **선언**하면
엔진이 진행률을 보고하고, 차면 **코드 수정 없이 저절로 켜진다.**

```ts
requires: { field: 'atmIv', sessions: 20, source: 'gex', why: '...' }
```

응답:
```json
{ "available": false,
  "readiness": { "have": 24, "need": 20, "lastDate": "2026-08-28", "stale": true },
  "reason": "자료가 멈춰 있음 — atmIv 마지막 2026-08-28, 옵션은 2026-08-31 세션" }
```

**두 가지를 «둘 다» 봐야 한다:**
1. `have >= need` — 충분히 쌓였나
2. `lastDate === optionSession` — **지금도 쌓이고 있나**

②를 빼면 «쌓였지만 며칠 전에 멈춘» 자료로 순위를 낸다. 실제로 그랬다(아래).

## 실측으로 데인 함정 8가지

| # | 함정 | 증상 | 막은 법 |
|---|---|---|---|
| 1 | **만기 롤오버** | 같은 날 NVDA 콜OI 107,121~1,985,592. 「평소의 6배」 22σ 허수 | 그날 총 OI 최대 스냅샷을 대표로 + 같은 규모 날끼리만 비교 |
| 2 | **분모 붕괴** | 비교일이 비슷하면 MAD→0, z 가 42σ 로 폭발 | 산포/중앙값 하한 + 순위는 σ 아닌 «배수» |
| 3 | **시장 교란** | 시장이 조용한 날엔 전 종목이 이탈로 보임(상위 6 중 4개) | 그날 시장 중앙값으로 나눠 «시장 대비»만 |
| 4 | **날짜 혼입** | 옵션은 오늘인데 다크풀만 3일 전 → 묵은 값이 1위 | 날짜 불일치면 랭킹에서 제외 |
| 5 | **죽은 필드** | ivSkew 300행 전부 0 | 축에서 제외 |
| 6 | **라벨 불일치** | `pcr` 은 OI 기준인데 「풋콜 비율」로 쓰면 거래량으로 읽힘 | 라벨에 기준 명시 |
| 7 | **생산자 분리** | 프리미엄 행과 OI 행이 달라 둘 다 쓰는 랭킹이 0건 | 둘 다 든 행을 찾아 쓴다(섞지 않는다) |
| 8 | **행 ≠ 세션** | 15분 스냅샷을 세어 «20세션»이 «1,312 표본»이 됨 | `dailyValues()` — 하루 한 값 |
