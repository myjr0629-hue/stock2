## 2. 원인은 두 갈래다

### (a) 정상 — 현물이 닫혀 있다
`^SOX`(금 17:15, 52.7h) · `^TNX`(금 14:59, 55.0h) · `^VIX`(금 16:15) · 2s10s(재무부, 09-04).
값 자체는 맞다. 주말이니 안 움직이는 게 맞다.

### (b) 결함 — 야후 선물 피드가 «멈춘 채 타임스탬프만 전진»
야후 원본 직접 확인:

- `NQ=F/ES=F/RTY=F/GC=F/CL=F` → `range=1d&interval=1m` 이 **봉 0개**
- `range=5d&interval=5m` 로 보면 평일은 하루 275봉인데 **09-06(일)은 21:53에 1봉뿐**이고 그 값이 금요일 종가
- 그런데 `meta.regularMarketTime` 은 **매 분 전진**(21:48 → 21:51 → 21:57)
- 결과: 우리 `marketAgeSec` 이 650초로 계산 → “11분 전 시세”처럼 보임

**매주 반복되는 구조가 아니다.** 직전 4번의 일요일(08-09/16/23/30)은 18~23시 6봉 정상.
**오늘만** 야후가 일요일 세션을 못 받았다.

같은 시각 FMP 대조 — **선물은 실제로 거래 중이었다**:
- `ESUSD` 7,720.5 · 거래량 18,262 · prevClose 7,722.0
- `GCUSD` 4,458.7 (−0.40%) · 거래량 13,025 · prevClose 4,476.6 ← 우리는 **0.00%** 로 표시 중이었다
- (요금제 제한: NQ·RTY·CL·YM·DX 는 우리 FMP 플랜에서 막힘. ES·GC·SI·BTC 만 허용)

## 3. 왜 화면이 «LIVE» 라고 했나 — 감지 수단 자체가 없었다

- `market-feed/route.ts` 가 `isStale: false` 를 **하드코딩**. 페치 성공 여부일 뿐 값의 나이와 무관.
  → 55시간 된 US10Y 도 `isStale:false, status:"OK"`.
- `isFreshFeedFactor()` 는 `marketAgeSec` 을 믿는다 — **야후가 부풀리는 바로 그 필드**.
- `futuresLive` 는 `isCmeGlobexActive()`, 즉 **시계만** 본다. 데이터를 안 본다.

세 겹이 전부 «벤더가 정직하다»를 전제한다.

## 4. 수리 — 조작 불가능한 근거를 하나 만든다

벤더는 타임스탬프를 전진시킬 수 있지만 **값이 바뀐 시각은 못 만든다.**

| 파일 | 변경 |
|---|---|
| `services/yahooFinanceHub.ts` | `YahooQuote.lastChangeAt` 추가 |
| `api/cron/market-feed/route.ts` | 값이 실제로 바뀐 순간만 `lastChangeAt` 갱신·승계 |
| `services/macroHubProvider.ts` | `frozenSec` 를 응답에 실음 + 캐시 키 `macro:snapshot:v1 → v2` |
| `app-view/dash/page.tsx` | `isFreshFeedFactor` 가 `frozenSec` 를 **가장 먼저** 검사 · LIVE 배지 = 시계 AND 데이터 · 매크로 라이브 점도 동일 · `DELAYED` 문구 3개 국어 |

### 임계값 45분(2700초)의 근거 — 실측
정상 세션에서 «값이 안 바뀐 최장 구간»(1분봉 5일치):

```
^TNX 33분 · ^VIX 16분 · BTC 13분 · DXY 10분 · ES 6분 · NQ 3분 · GC 3분 · ^SOX 1분
```
가장 느린 `^TNX`(33분)보다 넉넉히 위 → 정상 장중 오탐 0, 오늘 같은 5시간 정지는 확실히 포착.

### 롤아웃 함정 하나를 피했다
값이 그대로인데 이전 기록이 없을 때(=이 코드 배포 직전 항목) `prev.updatedAt` 을 넣으면
**금요일에 굳은 값이 «1분 전 값»으로 둔갑**한다. 그 경우엔 `undefined`(=모름) 로 둔다.
모르면 라이브라고 말하지 않는다.

## 6. 남은 것 / 알고 있는 한계

- **값을 «움직이게» 만들지는 못한다.** 야후가 안 주면 안 준다. 이번 수리는
  «틀린 값을 맞다고 말하지 않는다»까지다.
- FMP 폴백은 요금제상 **ES·GC·SI·BTC 만** 가능(NQ·RTY·CL 불가) → 절반만 살리면
  “S&P 는 살아 있는데 나스닥은 금요일값” 이라는 더 헷갈리는 화면이 된다. 별건으로 판단 필요.
- `pulseStatusLabel` / `pulseStatusClass` 는 9차 레이아웃에서 렌더되지 않는 **죽은 변수**(9차 이전 잔재).
