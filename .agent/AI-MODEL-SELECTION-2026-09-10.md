# AI 모델 선택 — 실측 근거 (2026-09-10)

## 왜 이 문서가 있나
대표: 「소넷은 가격 측면에서 사용할 필요 없을 것 같다. **호출량을 올려주는 것이 가장 좋을 것**이고,
과하게 필요 없는 곳은 가벼운 것을 써도 되니까 조사를 해봐. **실제 호출해서 결과도 보고**해줘」

추측으로 정하지 않았다. 우리 실제 프롬프트로 여러 모델을 돌려 결과를 보고 정했다.

## 1. 결정적 발견 — 묶여 있는 것은 «호출 수»뿐이다

```
Claude Haiku 4.5   요청/분(RPM)   10 / 10,000   ← 0.1% 로 묶임
Claude Haiku 4.5   토큰/분(TPM)   5,000,000 / 5,000,000   ← 100% 정상
Claude Sonnet 4.6  토큰/분        6,000,000 / 6,000,000   ← 100% 정상
Nova Micro/Lite    요청/분        200 / 4,000   (5%)
그 외 30여 모델    요청/분        100 / 10,000  (1%)
```

두 가지가 따라 나온다.
1. **한 콜에 더 담는 투자는 거의 공짜다** — 섹터 헤드라인 10개를 10콜이 아니라 1콜로.
2. **호출량이 필요한 기능은 다른 모델로 옮기면 RPM 이 10~20배** — AWS 에 요청할 필요가 없다.

## 2. 절대 가격 (AWS 요금 API 실측 · us-east-1 · 1M 토큰)

| 모델 | 입력 | 출력 | Haiku 대비 |
|---|---|---|---|
| Nova Micro | $0.03 | $0.14 | 1/37 |
| **Nova Lite** | **$0.06** | **$0.24** | **1/20** |
| GLM 4.7 Flash | $0.12 | $0.70 | 1/8 |
| Gemma 3 27B | $0.40 | $0.67 | 1/6 |
| Qwen3 32B | $0.26 | $1.05 | 1/4 |
| **Claude Haiku 4.5** | **$1.10** | **$5.50** | 기준 |
| Claude Sonnet 4 | $3.00 | $15.00 | 2.7배 |

> 현재 **실청구액은 $0** — AWS 크레딧이 덮고 있다. Bedrock 항목(`Claude Haiku 4.5`,
> `Claude Sonnet 4`)은 Cost Explorer 에 잡히는데 금액이 0이다. 크레딧이 소진되면
> 위 단가가 실제 청구가 된다(현 사용량 기준 Haiku 전량 월 약 $1,040).

## 3. 실제 호출 결과 — **가격만 보면 안 된다**

### 작업 A · 뉴스 현지화 (우리 news-digest 프롬프트 그대로)
| 모델 | 통과 | 속도 | 5건 1회 |
|---|---|---|---|
| **Nova Lite** | **3/3** | 8.1초 | **$0.000424** |
| Claude Haiku 4.5 | 2/3 | 19.9초 | $0.0147 |
→ **대등**. 35배 싸고 2.5배 빠르다.

다만 «깊이»는 다르다:
- Nova Lite 「만약 이란의 전쟁 고조가 지속된다면, 원유 가격 상승에 대한 재평가가 불가피합니다」
- Haiku 「… 이는 **S&P 500 -0.48% 하락과 VIX +4.71% 상승으로 나타난 위험자산 회피 심화와 연결**될 수 있습니다」
  → Haiku 만 오늘 시장 데이터를 끌어와 뉴스와 엮는다.

### 작업 B · 실적 «관전 포인트»에 깊이 요구
| 모델 | 결과 |
|---|---|
| Nova Lite | 「메모리 가격 상승으로 인한 수익 증가가 **예상됩니다**」 ← 금지한 예측 표현<br>「회원 유지 비용을 주목하세요; 회원 유지 비용은 운영 효율성을 반영합니다」 ← 동어반복 |
| **Haiku** | 「DRAM·낸드 평균판매가(ASP) 추이와 서버 수요 강도; 메모리 사이클 회복 지속 여부가 분기 수익성을 결정」<br>「클라우드 인프라(OCI) 매출 성장률…」「FICC 거래 수익…」「풀프라이스 상품 비중…」 |

**깊이를 요구하면 가벼운 모델은 오히려 나빠진다** — 아는 척을 하다가 규칙을 어긴다.

### 그 밖에 실측으로 탈락한 것
- **Qwen3 32B**: $10B 를 「**10억 달러**」로 오역 — 금융 앱에서 치명적
- **GLM 4.7 Flash**: NVIDIA 를 「**나이벡스**」, Anthropic 을 「안토피에」
- **Llama 3.3 70B**: 3/9 실패, 「분산이 높다」
- **Nova Micro**: 「라글러 META」(laggard 음차), Anthropic→「인트로픽」

> ★ **형식 검사는 이 오류를 하나도 못 잡았다.** 길이·언어·JSON 전부 통과인데 숫자가 틀렸다.
> 싼 모델을 쓰려면 검증이 «형식»이 아니라 **«숫자·고유명사»** 를 봐야 한다.

## 4. 최종 배치

| 자리 | 모델 | 근거 |
|---|---|---|
| 플로우 상세 시나리오 · 커맨드 심층분석 | Haiku | 추론 품질이 상품 자체 |
| 아침 브리핑 | Sonnet 4 (EC2) | 기존 유지 |
| 가디언 뉴스 다이제스트 | Haiku | 시장 데이터와 엮는 깊이가 값어치 |
| 섹터 판정문 (10섹터 1콜) | Haiku | 한 줄 카피는 Haiku 가 확연히 낫다 |
| **실적 캘린더 관전 포인트** | **Haiku** | 처음 Nova Lite 로 갔다가 «깊이» 요구에 무너져 되돌림 |
| **종목별 뉴스** | **Nova Lite** | 현지화 작업 · 종목마다 호출 → RPM 200 이 구조적으로 필요 |

**Sonnet 은 쓰지 않는다** (대표 판단). 호출 한도가 Haiku 와 같아 이점이 없고 2.7배 비싸다.

## 5. 이날 만든 것
- `/api/cron/sector-headlines` — 10섹터 × 3개국어를 **1콜**로. 하루 9콜.
- `/api/cron/earnings-brief` — 실적 캘린더 162종목에 회사명·관전 포인트.
  **새 종목만** 만들고 이미 있으면 즉시 종료(호출 0건). TTL 30일.
- `/api/live/ticker-news` — 종목별 뉴스 3개국어. 캐시 30분·종목별.

## 6. 사고와 교훈 (같은 날)
1. **예열이 캐시를 오염시켰다** — 두 AI 라우트가 화면이 계산한 입력을 받아야 하는데
   티커만 보내 「데이터 부재로 분석 불가」가 캐시에 앉았다(9종목 중 8개).
   → 생성 전 가드(422) + 읽을 때 폐기, 예열 중단. [[prewarming-poisons-caches-when-inputs-are-client-computed]]
2. **프롬프트의 «예시»가 오역을 만들었다** — 「Anthropic→앤스로픽, NVIDIA→엔비디아」를
   예시로 줬더니 NVIDIA 를 「앤스로픽」으로 3번 오역. 예시를 걷어내니 0/5.
   → 예시 대신 규칙(「원문에 없는 회사명 금지」) + 기계 검증.
3. **예측 표현 정규식은 어미 변형까지** — `예상됩니다` 만 막으면 「예상**됨**」이 샌다.
4. **CSS 는 부모 구조를 확인하고 쓴다** — `.ecR` 이 flex 인데 `grid-column` 을 써서
   실적 캘린더 행이 전부 겹쳤다. 실화면을 안 봤으면 그대로 나갔다.
