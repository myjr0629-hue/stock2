## 0. 한 줄 결론

**알파스코어는 지금 실사용(자동매매·화면 신뢰 문구) 요건을 충족하지 못한다.** 세 가지 이유가 동시에 성립한다.

1. **예측력이 통계적으로 입증되지 않았다.** 전 세대(V4.6~V8) 실시간 IC 는 0 또는 음수. 현행 XS-2.0 의 최선 실측은 **IC +0.094(t=1.96, 15일, 8/7)** — 중첩창 보정(유효표본≈1/3)을 하면 t≈1.1, 거래비용 0 가정. 사전등록 게이트 **0/3**, 7/30 «상위데실 α −0.103%» 로 자동차단 뒤 9/2 대표 지시로 보류.
2. **엔진이 죽어 있다.** `signum-xs` 가 **9/1 부터 매일 "universe too small: 0" 으로 실패**(마지막 점수 8/31). 원인은 Intrinio 이관으로 대량 수집기가 퇴역해 원천 `signum-unified-cache` 가 **8/28 13:05 이후 미갱신**(유니버스 1,774행 중 9/1 이후 갱신 0) → 좀비 가드(4일)가 전부 폐기. 알림이 없어 16일간 아무도 몰랐고, **앱은 9/7경부터 구엔진 V8 점수를 «컨텍스트 스코어» 로 내보내는 중**(운영 API 실호출: engineVersion 8.0.0).
3. **실전 체결이 페이퍼 수익의 약 15%만 실현했다.** 같은 전략·같은 종목·같은 사이징으로 무마찰 페이퍼 **+32.1%** vs 실시간 체결 트윈 **+5.4%**(7/20~9/15, SPY +1.9%). 트윈트랙 설계가 측정하려던 «체결비용»이 알파의 대부분을 먹는다.

**따라서 개인 자동매매 실주문은 지금 열면 안 된다.** 다만 인프라(토스 실행기·콘솔·저널·킬스위치·게이트)는 실제로 만들어져 있고 설계 수준이 높다. 순서는 **복구(P0) → 재검증(P1) → 엔진 재구성(P2) → 그다음에 실주문(P3)** 이다. 보안 2건은 즉시.

### 5-3. 사용자 화면 영향

### 6-2. 만들었지만 미가동 / 계획만
- RT-2.0.0 실주문 어댑터(저장소에 있음, EC2 는 1.0.1) · B단계 배관 테스트(실행 기록 없음) · C단계 소액 실계좌(게이트 0/3) · 브레이킹 알림(섀도, `BREAKING_LIVE` 미설정) · `signum-backtest` 테이블(0행) · Alpaca/KIS 등(표에만 존재, 코드 0) · Live Modulation 계층(XS_MASTER_PLAN 2단계).

### 6-3. «개인 자동매매» 에 필요한 것 (지금 기준)
1. **신호 복구** 없이는 아무것도 없다(9/1 이후 점수 0).
2. **게이트 통과 전 실주문 금지** — 시스템 자체가 그렇게 설계됐고(calib-contra 자동차단), 트윈트랙이 «체결비용이 알파를 먹는다» 를 실측했다.
3. 규모: $1,000/30 = **$44 슬롯** 은 소형주 스프레드에 취약. 실주문은 최소 수천~1만 달러 규모 + **지정가**(시가 시장가 금지) + 스프레드 필터가 전제.
4. 벤치마크(SPY) 복구 없이는 성공기준 ① 판정 불가.
5. 지연은 문제 아님(22:10 UTC 점수 → 익일 09:30 ET 진입 — 야간 배치로 충분).

## 8. 개선안 — 우선순위

**P0 · 복구 (이번 주, 측정을 다시 살리는 일)**
- `signum-xs` 원천 복구: unified-cache 대량 갱신기를 Intrinio 시대 파이프라인에 재연결하거나, XS 가 `signum-harvest`/`gex-history` 등 살아 있는 원천을 직접 읽도록 어댑터 교체. 복구 후 좀비 가드 4일 규칙은 유지.
- CloudWatch 알람 3종: `signum-xs` 에러/`universe<40`, unified-cache 신선도(유니버스 행 24h 이내 갱신 비율), `cache:xs:scores` 부재. 슬랙/푸시로.
- SPY 종가 캡처 복구(성공기준 ① 계산).
- 앱의 무음 폴백 차단: XS 부재 시 V8 대신 «점수 준비 중» 표시(`XS_DISPLAY` 분기 확장), 리포트 카드 powerScore 라벨 분리.

**P1 · 재검증 (복구 후 4~6주, 사전등록 유지)**
- BACKLOG §② «이관 영향 백테스트» 착수: 이관 전(~8/28) vs 후 데이터로 팩터별 IC 대조.
- 통계 보정 표준화: 블록 부트스트랩/Newey-West t, 유효표본 N/3 표기, hit 정의 통일(>0.25% 시장조정), 지평 T+3 고정(슬랙 금지).
- 비용 반영: 실시간 트윈의 실측 체결가(호가·스프레드)를 백테스트 비용 모델로 채택.
- 게이트 ①·② 자동 판정 구현(콘솔 `pass:false` 고정 제거), 20일 V8 맞대결 기록.
- 약세장 표본 확보 전에는 «조건부» 라벨 유지.

**P2 · 엔진 (검증 결과에 따라)**
- 죽은 팩터 정리(gexInv·dGex5·ivLow 롤링 IC 음수), 반전·SMA 계열은 «공개된 단기반전 효과» 로 정직하게 명명.
- «변환이 알파를 만든다» 를 분해: 피어잔차·EMA·백분위를 각각 끄고 IC 재측정. 변환 없이 0 이면 팩터 세트를 바꿔야 한다.
- T+1 무신호 실측을 존중해 T+3 지평만 제품화. Live Modulation 은 Base 통과 뒤.

**P3 · 자동매매 (게이트 3/3 + 비용 반영 양수 뒤에만)**
- B단계 배관(최소단위 왕복)만 먼저. 실주문은 지정가·스프레드 필터·규모 ≥ $10k·킬스위치 의미 통일(주간 킬 재개 방식 트랙 간 불일치 해소).
- RT-2.0.0 배포는 보안 1번 해결이 선행조건.
