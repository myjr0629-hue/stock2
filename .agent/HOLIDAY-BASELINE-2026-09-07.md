# 휴장일에 «전 종목 보합»으로 나가던 버그 (2026-09-07 노동절)

## 무엇이 보였나

노동절 오후, 화면의 등락률이 이랬다.

| 종목 | 화면 | 실제 (직전장 9/4) |
|---|---|---|
| TSLA | **-0.05%** | **-5.92%** |
| MRVL | **+0.04%** | **+7.05%** |
| NFLX | **+0.01%** | **-5.35%** |
| MU | -0.17% | +6.10% |

22종목 중 **14종목**이 ±0.0x% 였다.
히트맵은 **10개 섹터 전부 0.00% · 0▲ 0▼** 이면서 「직전 거래일 마감값입니다」라고
써 있었다 — 문구가 거짓말을 하고 있었다.

## 왜 못 잡았나

`scripts/audit-screen-numbers.js` 는 **20종목 전부 «이상 없음»** 을 냈다.
검사기가 «자기들끼리 맞는가»만 봤기 때문이다:

```
changePct(-0.0002)  ==  display(-0.02%)   → 통과
```

**같은 원인으로 틀린 두 값은 서로 완벽하게 맞는다.**
정답은 화면 밖에 있다 — 일봉의 마지막 두 종가.

## 뿌리는 하나, 얼굴은 셋

세 군데가 각자 «오늘»을 잘못 알고 있었다.

### ① `/api/live/ticker` — 벤더 prevClose 의 정의
`_intrinio.prevClose` 는 «마지막 정규장의 **하나 앞**»이다.
휴장일엔 스냅샷이 굴러가 그 값이 «마지막 정규장 **그 자체**»가 된다.
표시가와 기준선이 같아지니 등락률이 0.

**지문**: `baseline.dateET` 가 표시 중인 세션 날짜와 같거나 그 뒤다.
기준선은 표시 세션보다 반드시 **앞**이어야 한다 — 아니면 자기 자신과 비교한 것이다.

> 4종목(MSFT·GOOGL·AMZN·META)만 우연히 맞았다. `liveLast` 가 없어
> `changePctFrac` 이 null 이 되고 «값 없음» 폴백이 직전 세션 등락률로 메웠다.
> **폴백이 근본 원인을 마스크하고 있었다.**

### ② `/api/live/quotes` — 휴일 재구성의 발동 조건
휴일 재구성(`reconstructLastSession`)은 이미 있었는데 게이트가 `!day.c` 하나였다.
이번 휴장일에 벤더는 `day.c` 를 **비우지도, 전일 종가로 복사하지도 않고**
«금요일의 굳은 마지막 체결가»(NVDA 230.31, 공식 종가는 230.36)를 넣었다.
값이 있으니 모든 값-기반 검사를 통과한다.

**교훈: 휴장은 값으로 추측하지 말고 달력으로 판정한다.** 우리는 이미 안다
(`marketStatusProvider.isHoliday`).

### ③ `currentEtTradingDate()` — 주말은 건너뛰고 휴장은 안 건너뛰었다
```ts
while (et.getDay() === 0 || et.getDay() === 6) et.setDate(et.getDate() - 1);
// ↑ 휴장일은 그대로 «오늘»
```
노동절에 09-07 을 돌려주니 벌크 EOD 최신일(09-04)이 «뒤처진 것»으로 판정돼
`prevClose` 가 금요일 종가로 잡혔다.

**이 함수 하나가 히트맵 · 인텔 · 섹터 라우트 10종 · Market Breadth 를 동시에 망가뜨렸다.**
같은 계산이 섹터 라우트마다 복사돼 있어서, 라우트를 하나씩 고쳤다면 반드시 빠졌다.

## 부하에서만 나던 네 번째 얼굴

`reconstructLastSession` 은 티커마다 벤더 호출 2회를 **매 요청마다** 했다.
프리뷰에선 22/22 맞았는데 **운영에선 8종목 중 3종목만** 맞았다. 차이는 부하다 —
쿼터에 걸린 티커가 «조용히 누락»되고, 누락된 티커는 호출부의 깨진 폴백으로 되돌아간다.

→ Redis 에 날짜별로 캐시 + 실패 시 1회 재시도 + 누락을 로그로 남긴다.
직전 «완료된» 세션 종가는 다음 개장까지 변하지 않는다.

## 검사기를 고쳤다

`scripts/audit-screen-numbers.js` 에 «정답 대조» 3종을 넣었다.

| 코드 | 무엇을 본다 |
|---|---|
| `TRUTH_MISMATCH` | 표시 등락률 vs 일봉 마지막 두 종가 |
| `BASE_IS_SELF` | 기준선이 «표시 중인 세션 그 자체»인가 |
| `QUOTES_TRUTH_MISMATCH` | `/api/live/quotes` 도 같은 정답을 보는가 (생산자가 둘이다) |

## 이번에 밟은 함정

1. **프리뷰와 운영이 같은 Redis 를 쓴다.** 프리뷰에서 «아직 틀림»으로 나온 2종목은
   운영(미수정)이 60초 캐시에 방금 써넣은 값이었다. 다시 재니 맞았다.
   → 프리뷰 측정이 운영 쓰기에 오염될 수 있다. 재현되는지 반드시 두 번 잰다.
2. **배포 URL 을 SHA 로 확인하지 않으면 «안 고쳐졌다»는 오진이 난다.**
   `vercel ls --meta githubCommitSha=$(git rev-parse HEAD)` 로만 확인할 것.
3. **소스 grep 은 62곳을 신고했지만 화면은 1곳이었다.** 정본은 화면이다.
