# 쿠폰 흐름 결제 분리 — 실기기 확인표 (2026-10-23 r3)

상태: 전 항목 미실행. 실기기 확인·대표 승인 전 운영 병합·배포 금지(RELEASE-E2E-CHECKLIST C절).
실제 쿠폰 번호·계정·결제 식별자는 이 문서에 기록하지 않는다.

## 설계(r3 — 관문 보류 2회 뒤 운영 세션 확정안)

- 안드로이드 «🎟 쿠폰 코드 입력» 시트에는 구매 단추가 없다. 시트·`couponGuide.ts`는 `useProStatus().purchase`·`purchasePackage`·`purchasePro`를 부르지 않는다(r1·r2의 `[계속]`·체크박스·`runCouponPurchase` 삭제).
- 단추 하나 = «① Play 스토어에서 적용»: `play.google.com/redeem`을 연다(`openExternalUrl`).
- 앱이 가려졌다가(appStateChange 비활성·visibilitychange hidden) 다시 보이면 RevenueCat을 새로 읽는다: `refreshProAfterRedeem('url')` = 캐시 무효화 → getCustomerInfo → syncPurchases → 다시 → 3초·8초.
  - PRO 활성 → «적용됨»(공용 상태 알림, 1.5초 뒤 닫힘).
  - 아니면 → «아직 적용되지 않았습니다 — 등록 화면에서 코드를 입력해 주세요». 다시 Play 스토어에 다녀오면 한 번 더 읽는다(확인 중에 다녀와도 끝난 뒤 한 번 더 — 관문 10230232 수리).
  - 가려진 적 없는 «보임» 신호는 복귀로 보지 않는다. `browserFinished`는 쓰지 않는다(맞춤 탭이 Play 스토어 앱으로 넘기며 곧 닫힐 수 있음).
- 열기 실패 → «코드 등록 화면을 열 수 없습니다 — Play 스토어 앱에서 직접 등록»(r1 문구). 다시 누를 수 있다(결제 경로가 없으므로).
- 웹 쿠폰 화면(안드로이드 일반·인앱·선물): «② 이어서 «구독»…» → «② 등록 후 앱에서 PRO 확인», «구독 화면이 안 나오면 … 계속 → «구독»» 줄 삭제. 무료 미표시 경고 줄(r1)은 유지.
- 설정 «쿠폰 코드 입력» 행 아래 줄: «결제 창에서 코드 입력 → «구독»» → «Play 스토어 → 결제 및 정기 결제 → 코드 사용»(시트 ① 과 같은 말).
- 일반 페이월(ProPaywall)·결제 SDK·iOS 코드 사용 시트는 바꾸지 않았다.

## 앱 반영 경로

앱은 원격 웹을 연다(`capacitor.config.ts`·안드 `assets/capacitor.config.json` server.url = `https://www.signumhq.com/en/app-view/dash`). 웹 배포만으로 안드·iOS 앱 화면에 반영된다. 필요한 네이티브 플러그인(@capacitor/browser·@capacitor/app·RevenueCat)은 현재 안드 바이너리에 이미 있다.

## 남은 위험

- 구글 공식·RevenueCat 문서와 10/6 대표 실기기: Play 스토어에서 쓴 구독 코드는 «저장»만 되고, 앱 안 구독 구매 때 자동 적용된다. 그렇다면 쿠폰 흐름만으로는 PRO가 켜지지 않고, 사용자는 일반 페이월 구독(결제 창 30일 무료 표시 확인)을 거쳐야 한다. 쿠폰 흐름은 이 구매를 대신하지 않는다 — 결제 안전이 우선.
- 맞춤(custom) Play 코드는 앱 안 결제 창에서만 쓸 수 있다(구글 문서). 현재 안드 배포는 일회용 번호 풀이라 영향 없음.
