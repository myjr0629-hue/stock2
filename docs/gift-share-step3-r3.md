# 공유 완료 토큰 재사용 관문 수리 3차

## 결과 요약

같은 브랜치의 관문 `gate-feat_gift-share-step3-10211609.md`와 `gate-feat_gift-share-step3-10211928.md`, 이전 지시·결과를 끝까지 읽었다. 2차 관문의 공유 완료 토큰 재사용 결함을 수정했다. 플래그·화면 라벨·문구·배치·기준일 값은 변경하지 않았다.

## 원인과 수정

공유 시트가 열린 동안 설정 재조회에 실패하거나 재고가 일시 소진되면 `refresh()`가 메모리의 `ready`를 비운다. 기존 `complete()`는 `ready`가 있어야 저장된 토큰을 제거했으므로, 공유에 성공해도 미전송 토큰이 남았다. 설정 복구 후 같은 토큰이 복원돼 다음 사람에게 다시 전송됐다.

완료 처리는 실제 전송한 페이로드 URL에서 유효한 토큰을 추출한다. 공유·복사 성공이면 현재 준비 상태와 영속 저장소에서 그 토큰만 소비한다. 설정 재조회로 준비 상태가 사라져도 영속 저장소의 소비를 수행한다. 같은 완료 통지를 다시 받아도 다른 토큰은 지우지 않으며 추가 발행하지 않는다. 취소·실패에는 소비하지 않는다.

## 공유 함수의 모든 호출자와 영향

`createGiftPreparation()`의 운영 인스턴스는 `giftPreparation` 하나다. `usePreparedGift()`를 통해 다음 세 호출자에 연결된다. 모두 실제 전송한 페이로드와 전송 결과를 `complete()`에 넘긴다.

| 직접 호출자 | 연결 표면 | 영향·검증 |
|---|---|---|
| `ShareButton` | 앱 종목·랭킹, WIM | 종목·랭킹의 완료 토큰 소비 수리. WIM은 원래 페이로드 사용. 기존 JSX·공유 전 await 부재 시험 통과 |
| `useInviteShare` → `InviteShareButton` | 오늘 볼 것·관심종목 AI 한 줄·실적 | 완료 토큰 소비 수리. 기존 설명·주소·ref 유지 시험과 초대·랜딩 회귀 통과 |
| `useGiftShare` | 설정·`GiftDashButton`·`GiftAnnounceSheet` | 완료 토큰 소비 수리. 기존 화면 JSX와 선물·안내 회귀 통과 |

호출부·공유 전송기·서버 발행/등록 API·Lua는 수정하지 않았다. 꺼짐에는 기존 페이로드 객체를 그대로 반환한다. 기존 공유/복사 바이트 동일성과 서버 응답 144조합·템플릿 48조합 동일성 시험이 통과했다.

## 재현 시험과 확인 결과

`tests/giftShareClient.test.ts`에 재현 시험 6개와 취소/실패 보존 시험 1개를 추가했다.

- 설정 조회 실패·일시 소진·공유 도중 플래그 꺼짐 각각에서 공유/복사 완료의 6조합을 검사한다. 수정 전 6개 모두 실패했고 수정 후 통과했다.
- 완료 뒤 저장소에서 토큰이 제거되고, 다른 열린 문서가 그 토큰을 다시 내보내지 않으며, 복구·문서 재진입 때 새 토큰만 발행하는지 검사한다.
- 이전 완료 통지의 재사용이 다음 토큰을 지우거나 추가 발행하지 않는지 검사한다.
- 장애·소진 뒤 취소/실패의 4조합에서는 미전송 토큰을 보존하는지 검사한다.
- 클라이언트 총 18개 통과. 기존 꺼짐 바이트 동일성·화면 JSX 동일성·이전 관문 회귀 포함.
- 전체 오프라인 시험 278개 파일을 1회 실행해 278개 통과·실패 0개. `giftShare.test.ts`의 서버 20개와 Lua 모의·대조군 14개도 통과했다. 실제 Redis 시험 1묶음은 로컬 실행 파일이 없어 건너뛰었다.
- 전체 타입 검사를 1회 실행해 종료 코드 0·진단 0을 확인했다.
- 추가 Python 프로세스 시험 22개도 최소 환경과 공용 잠금 아래 종료 코드 0으로 통과했다. 실제 브라우저 대신 격리된 Perl 더미를 사용한다.
- 변경 3개 파일의 비밀값 검사와 `git diff --check`가 통과했다.

실행 명령은 다음과 같다. 무거운 검사는 같은 공용 잠금으로 직렬 실행한다.

```sh
/usr/bin/lockf -k /tmp/signum-heavy.lock node scripts/run-offline-tests.cjs
/usr/bin/lockf -k /tmp/signum-heavy.lock node node_modules/typescript/bin/tsc --noEmit --incremental false --pretty false
```

전체 실행 결과는 커밋하지 않는 `.logs/ux-gate/results.json`에 있다. 시험 실행기는 환경 파일 읽기와 외부 통신을 차단한다.

## 커밋 상태

브랜치는 `feat/gift-share-step3`다. 지정한 세 파일만 `git add`하려 했으나 공용 Git 메타데이터의 `index.lock` 생성이 `Operation not permitted`로 차단됐다. 권한 제한을 우회하지 않았다. 커밋은 미완료이며 변경은 작업공간에 저장되어 있다. 인계 패치는 `/tmp/signum-gift-share-step3-r3.patch`에 남긴다.

## 남은 위험

실제 Redis·실기기·메신저·스토어 등록·PRO 부여는 미검증이다. 준비는 재고 예약이 아니므로 전송 뒤 소진 가능성은 기존과 같다. 브라우저·스토어 콘솔에 접근하지 않았고 운영 데이터 쓰기·push·병합·배포는 수행하지 않았다. `.env*`와 실제 재고 코드 파일은 읽지 않았다.
