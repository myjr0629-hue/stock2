# 공유=선물 3단계 준비 및 실기기 확인표

## 현재 설계 (10/22 5차 — 자정 경계 근본 제거. 이 절이 아래 옛 서술보다 우선한다)

**설계 선택(근거 2줄)**: 등록 한도(기기·계정·IP·전체)를 «등록 처리 시각»이 아니라 기기가 보낸 «공유 완료 시각(at)»의 KST 날짜로 센다 — 기기가 그날 보낸 링크 수와 서버 셈이 같은 시각 하나에서 나오므로 재시도·응답 지연·유실이 언제 자정을 넘어도 «보낸 링크가 한도로 거부»될 길이 구조적으로 없다(관문 10220544·0553·0559·0607 같은 계열 4회의 공통 원인 = 두 셈이 다른 시계를 썼다).
«등록 불가면 일반 공유로 떨어뜨리기»만으로는 공유 순간(동기 클릭 경로)에 서버 상태를 알 수 없어 깨진 링크를 0으로 만들 수 없으므로 택하지 않았다; 끌어쓰기는 서버가 at ∈ [지금−48시간, 지금+10분]만 받아 막고, 기기 시계가 서버와 5분 넘게 다르면 선물 링크 자체를 만들지 않는다.

- **등록 요청**: `POST /api/gift/issue {token, at}`. at = 공유 완료 시각(기기 시계, ms). 서버 키 `issue:{kstDay(at)}:device|account|ip|all`, 보관 4일(345600초 — 그 날짜로 최대 48시간+하루 뒤까지 등록되므로 만료로 셈이 0이 되는 일 없음). at 이 없거나 범위 밖이면 일반 설치 폴백(저장소 무호출).
- **기기 장부(10/22 6차, 관문 10222309 수리)**: 날짜별 보낸 수·잡아 둔 몫(hold)·재시도 장부를 IndexedDB(`signumhq-gift`/`kv`/`state.v1`) 한 값으로 두고, 모든 변경을 readwrite 트랜잭션 하나로 한다(`src/lib/giftShare/state.ts`). 브라우저가 같은 저장소의 readwrite 트랜잭션을 탭·연결과 무관하게 직렬 실행하므로 «한도 검사 + 예약»이 탭 사이에서 원자적이다(localStorage 의 읽고-쓰기 교차로 두 탭이 같은 몫을 쓰던 결함 제거). IndexedDB 를 열 수 없으면 선물 문구 없이 일반 공유.
- **예약은 클릭 전에**: 화면 진입·복귀(refresh, 비동기)에서 «오늘 보낸 수 + 모든 문서의 잡음 < 한도(앱 3·웹 1)»일 때만 새 토큰 하나를 잡아 둔다(준비 몫 3분, 화면이 보이는 동안 60초마다 연장 — 닫히거나 새로 고친 문서의 몫은 3분 뒤 풀림). 클릭(payload, 동기)은 장부를 읽지 않고 준비된 토큰을 «한 번만» 내준 뒤 준비 칸을 비운다 — 같은 문서의 다른 단추가 같은 토큰을 받는 결함 제거(다음 준비 전 클릭은 일반 공유). 내준 토큰의 몫은 클릭 즉시 30분으로 연장한다(준비 몫이 90초 넘게 남았을 때만 싣는다).
- **완료**: 보냄(shared·copied·failed) → 같은 트랜잭션에서 잡음 제거 + kstDay(at) 보낸 수 +1 + 재시도 장부 추가, 동시에 at 으로 등록. 취소 → 그 토큰을 준비 칸으로 되돌림(다시 누르면 같은 토큰). 재시도 대상 선택·횟수 표시도 트랜잭션 안에서 해 여러 문서가 같은 토큰을 겹쳐 보내지 않는다.
- **완료 기록 실패 대비(관문 10222323 수리)**: 보냄 통지 때 장부 트랜잭션보다 먼저 토큰별 localStorage 표식(`signumhq.gift.pending.v1.<token>` = at)과 메모리 사본을 남긴다. 예약·재시도 트랜잭션은 표식을 «먼저 합친 뒤» 한도를 본다(같은 토큰은 `counted`로 한 번만 셈). 기록 트랜잭션이 실패하거나 문서가 그 전에 닫혀도 다음 트랜잭션이 셈을 복구한다. 시트 몫 연장이 실패하면 즉시 한 번 더, 그 뒤엔 60초 refresh 연장이 이어받는다(클릭 여유 90초).
- **재시도**: `{token, at, tries, last}` — 같은 at 을 그대로 보내 5분 간격·최대 5회·47시간 안(서버 48시간보다 1시간 짧게).
- **시계 확인**: `share-config` 켜짐 응답에만 `now`(서버 시각)를 더한다. 꺼짐 응답 `{enabled:false, available:false}`는 그대로.
- 남은 한계: 같은 계정의 다른 기기·같은 IP의 여러 사람·전체 400 은 기기에서 알 수 없다(한 기기만으로는 공유 날짜당 최대 3 < IP 10 이라 닿지 않음). 앱을 새로 고친 직후 최대 3분은 옛 문서의 준비 몫 때문에 그날 남은 선물이 한 칸 적게 보일 수 있다(일반 공유 쪽으로만 기움). 시트를 30분 넘게 띄워 두는 동안 다른 탭이 그 몫을 가져간 경우만 셈이 한도를 넘을 수 있다.

### 4차 재설계 (10/22 — 아래 중 «자정 경계»·«응답 날짜 반영»·«예약분» 서술은 5차로 대체)

관문 3회 보류(공유 전 자동 발행으로 일일 한도 소진·공유 완료 토큰 재사용·응답 유실 시 한도 소진)의 공통 원인은 «화면 진입 때 서버가 토큰을 발행»하는 구조였다. 이를 없앴다.

- **화면 진입**: `GET /api/gift/share-config`로 플래그·양 OS 재고만 확인한다. 선물 토큰은 기기에서 32바이트 무작위(base64url 43자)로 만든다. 서버 발행·한도 차감·저장 없음. 미전송 토큰은 저장하지 않으므로 재로딩·여러 문서가 한도를 쓰지 않고, 문서마다 토큰이 다르다.
- **공유 완료 뒤 1회 등록**: 공유 시트 `shared`·복사 `copied`, 그리고 `failed`(공유 전송기가 마지막 수단으로 주소를 수동 복사 창에 띄웠을 수 있음)일 때 `POST /api/gift/issue {token}`으로 그 토큰을 등록한다(기기·계정·IP·전체 한도 차감). 취소 `cancelled`만 등록하지 않는다. 등록 응답이 요청과 다른 KST 날짜에 오면 그날 횟수에도 1회 반영한다(자정 경계).
- **토큰 1회용**: 보낸 토큰은 즉시 폐기하고 다음 공유는 새 토큰을 쓴다. 같은 완료 통지는 한 번만 등록한다. 서버 `ISSUE_LUA`는 이미 있는 토큰을 한도 검사·차감 전에 `exists`로 끝낸다(재등록 거부, 응답 유실 재시도는 무해). 수신자 배정은 기존 `CLAIM_LUA`대로 토큰당 1명.
- **응답 유실**: 공유는 됐는데 등록 응답을 못 받은 토큰만 `signumhq.gift.sent.v1`에 남겨 5분 간격·최대 5회·7일 안에 같은 토큰으로 다시 등록한다. 다른 날(KST) 공유분은 오늘 서버 기기 한도를 쓸 수 있으므로 오늘 한도의 예약분으로 세고, 그날 첫 재시도 때 오늘 횟수에 1회 반영한다(재시도는 새 공유 준비보다 먼저 한다). 과대 계산은 일반 공유 쪽으로만 기운다.
- **폴백**: 재고 0(어느 한 OS라도)·설정 장애·확인 60초 초과·저장소 장애·앱 기기 열쇠 없음·기기 일일 한도(앱 3·웹 1, KST, `signumhq.gift.day.v1`) 도달이면 선물 문구 없이 일반 공유(기존 선물 전용 공유는 코드 없는 일반 설치 문구, 유효 ref 는 `from=gift`로 추천 귀속 유지).
- **꺼짐(GIFT_SHARE_ENABLED≠1)**: 원래 페이로드 객체를 그대로 반환하고 저장소·등록에 접근하지 않는다. `share-config`는 `{enabled:false, available:false}`만 반환(Redis 0). `/api/gift/issue`·`/api/gift/claim`은 기존대로 일반 설치 폴백.
- 남은 한계: 계정·IP·전체 한도(3·10·400)와 공유 직후 소진은 기기에서 알 수 없어, 그 경우 링크는 수신 시 기존 등록 폴백(일반 설치)로 간다.


## 결과 요약

플래그를 켜지 않고 기존 앱 공유에 선물 토큰 준비와 공유 본문 연결을 추가했다. 화면 라벨·배치·JSX·CSS는 바꾸지 않았다. 브라우저·계정·스토어 콘솔에 접근하지 않았고, 운영 Redis 쓰기·push·병합·배포도 하지 않았다. `.env*`와 실제 코드 파일은 읽지 않았다.

원인은 기존 앱 공유가 새 토큰 발행 API를 호출하지 않는다는 점이다. 또한 발행 성공은 재고 확보를 뜻하지 않는다. 화면 진입 시 공통 준비 상태가 플래그·양 OS 재고·일 한도를 확인한 뒤 토큰을 발행한다. 클릭은 준비된 페이로드를 동기로 만들고 곧바로 기존 공유 시트를 호출한다. 클릭 전에 API 응답을 기다리지 않는다.

꺼짐에는 기존 페이로드 객체 자체를 반환한다. 켜짐이고 준비됐을 때만 한국어·영어·일본어 선물 문구와 `/app?from=gift&…&gift=…`를 사용한다. 기존 콘텐츠 설명과 공개 주소도 본문에 보존한다. 공유 카드와 기존 선물 경로의 공개 초대자 `ref`도 보존한다. 기기 비공개 열쇠는 링크·본문·비콘에 넣지 않는다.

플래그 설정 조회는 60초 간격이며 화면 복귀에도 갱신한다. 같은 문서의 모든 공유 단추가 요청·토큰·타이머를 공유하고 숨겨진 문서에서는 정기 조회를 멈춘다. 미전송 토큰은 출처별 로컬 저장소에 보관해 문서를 다시 열어도 재사용한다. 공유 취소·실패에는 보존하고, 공유·복사가 끝나면 제거한 뒤 다음 토큰을 준비한다. 저장소를 읽거나 쓸 수 없으면 자동 발행하지 않는다. 복원한 토큰도 최신 설정·재고 확인을 통과해야 사용하며, 다른 문서가 이미 보낸 토큰은 클릭 시 제외한다. 재고 확인이 60초 이상 지났으면 일반 공유한다. 한쪽 OS라도 재고·일 한도가 없거나 조회·발행이 실패하면 선물 문구를 붙이지 않는다. 기존 선물 전용 공유도 이 경우 코드 없는 일반 설치 문구로 돌아가되 유효한 초대자 ref가 있으면 추천 태그를 유지한다. 켜짐 선물 링크는 발행 API와 같은 출처를 사용한다. 꺼짐에는 기존 선물 문구와 공용 링크가 그대로다.

새 `GET /api/gift/share-config`는 플래그와 준비 가능 여부만 반환한다. 꺼짐에는 Redis를 호출하지 않는다. 켜짐의 `AVAILABLE_LUA`는 유효 묶음·각 OS 첫 재고·일 한도만 읽고, 코드나 수량은 응답하지 않는다. 토큰 발행·등록·적재 Lua 및 기존 API는 변경하지 않았다.

## 재고 적재 점검

`scripts/gift-load-codes.mjs`를 끝까지 확인했으며 수정하지 않았다.

- 입력은 경로 인자로만 받는다. `realpath`로 심볼릭 링크를 풀고 현재 공개 저장소 내부와 `.git`이 있는 다른 체크아웃 내부를 거부한다. `.env*` 대상도 거부한다.
- 1MB·최대 1,000장 제한, OS별 형식, 파일 안 중복, 유효한 전용 묶음 메타데이터를 검사한다.
- 기본은 로컬 드라이런이다. `--apply`와 명시적인 `--target production` 또는 `preview`가 있어야 Redis 적재 단계에 진입한다. 연결값은 이미 주입된 환경변수만 사용한다.
- 적재 Lua는 묶음 재적재·다른 묶음의 같은 코드·기존 Play/초대자 미배정 풀·Play 배정 장부 중복을 검사한 뒤 원자적으로 적재한다.
- 성공 보고에는 OS와 적재 개수만 나온다. 실패에도 파일 경로·코드·인증값을 출력하지 않는다.
- 자동 중복 검사는 이미 게시한 코드·다른 환경·기존 iOS 전체 지급 이력까지 포괄하지 않는다. 운영 코디네이터가 배포용/보상용과 분리한 전용 재고라는 사실을 먼저 확인해야 한다.

검증 후 같은 브랜치에서 위 7개 파일을 `git add`했으나, 공용 Git 메타데이터의 `index.lock` 생성이 `Operation not permitted`로 차단됐다. 실제 경로에 심볼릭 링크가 없고 디렉터리 소유자 쓰기 권한이 있는 것은 확인했다. 현재 실행 권한에서는 커밋을 만들 수 없으며, 권한 제한을 우회하지 않았다. 변경 7개 파일은 작업공간에 저장되어 있고 인계 패치는 `/tmp/signum-gift-share-step3-r2.patch`에 남긴다. 커밋·push·병합·배포는 수행되지 않았다.

확인된 한계: 준비 조회와 실제 등록은 재고를 예약하지 않는다. 준비 후 다른 수신자가 마지막 코드를 사용하거나 날짜/한도가 바뀔 수 있다. 확인값은 최대 60초 유효하고, 이미 발송한 링크의 이후 소진은 서버의 기존 등록 폴백이 처리한다. 플래그 변경도 활성 화면에 최대 약 60초와 진행 중 요청 시간 뒤 반영된다. 즉시 배분 중단은 서버 등록 경로의 기존 플래그 검사에 따른다.

미확인: 실제 Redis 런타임, 기기별 공유 제스처·메신저 본문 보존·스토어 이동, 실제 상품 자격/기간/지역/갱신 설정, 설치 전후 링크 전달과 검증된 PRO, 로그의 쿼리/Location 마스킹. 위 실기기 표가 통과되기 전에는 켜지 않는다.
