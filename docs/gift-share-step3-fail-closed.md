# 예약 만료·완료 기록 유실 관문 수리

기준: `feat/gift-share-step3`, `354f79d53` 이후. 플래그·화면 JSX·라벨·공유 문구·서버 등록 API·Lua는 변경하지 않는다.

## 원인과 판정

기존 구현은 링크를 공유 시트에 넘긴 뒤 예약을 비동기로 연장했다. 연장 실패 또는 30분 경과로 예약이 풀려도 시트의 URL은 회수할 수 없었다. 다른 탭이 같은 몫을 사용한 뒤 원래 시트가 완료되면 서버 한도를 넘었다. 완료 장부와 완료 표식 저장이 함께 실패한 경우에는 문서 종료로 메모리 기록까지 없어졌다.

`client.ts`의 `issueToken()`이 URL 발급 직전의 유일한 판정 함수다. 설정·재고·확인 시각·예약 유효 기간·예약 플랫폼·중복 완료·미반영 완료 기록을 검사하고, 발급 표식을 동기로 저장한 뒤 재읽기까지 성공해야 토큰을 반환한다. 실패하면 기존 일반 공유 경로를 사용한다. 동기 `payload()`와 공유 전 사용자 제스처 흐름은 유지한다.

발급 표식은 완료 또는 취소 저장을 확인하기 전까지 지우지 않는다. 모든 한도 트랜잭션에서 최신 표식을 읽어 `issued` 예약으로 합친다. 이 예약은 시간·날짜 경과나 장부 보관 상한으로 제거하지 않는다. 발급 직후 IDB 저장이 실패해도 동기 표식이 몫을 보호하고, IDB 저장에 성공했다면 표식을 잃어도 IDB가 몫을 보존한다. 완료 저장이 확인되면 같은 몫을 해당 완료 날짜의 보낸 수로 옮긴다.

미발급 준비 예약은 기존처럼 만료된다. 취소 후 재사용은 취소 트랜잭션 저장 확인 뒤에만 허용한다. 취소 저장 대기 중 완료 통지가 들어오면 같은 토큰을 다시 발급하지 않는다. 예약 트랜잭션 대기 중 자정을 넘는 경우에도 실제 판정 시각의 한도를 사용한다.

## 공유 함수 호출자와 영향

- `giftPreparation` → `usePreparedGift()` → `ShareButton`: 종목·랭킹 공유에 같은 판정 적용. 다른 표면의 기존 경로 유지.
- `giftPreparation` → `usePreparedGift()` → `useInviteShare`: 추천 공유에 같은 판정 적용. 콘텐츠·ref 보존.
- `giftPreparation` → `usePreparedGift()` → `useGiftShare`: 기존 선물 입구에 같은 판정 적용. 선물 불가 시 기존 일반 안내 사용.
- `normalizeState()`·`trimState()`: 운영 호출자는 `idbAtomic()`, 시험 호출자는 `_giftStateMemory.ts`. `issued` 속성을 유지하고 미확정 몫을 잘라내지 않도록 변경. 기본 IDB 모의와 여러 탭 동시 예약 시험으로 검증.
- `recordSent()`와 공유 호출부는 변경하지 않는다. 타이머 재시도 인자는 제거하고 시험의 생성 호출을 맞췄다.

## 검증

외부 통신·환경 파일 읽기를 차단한 기존 오프라인 실행기를 공용 `lockf` 잠금 아래 실행했다.

- 관련 회귀 12파일 통과: 기존 선물·선물 안내·초대·랜딩·쿠폰·서버·Lua·적재 도구 및 클라이언트·자정 시험.
- 클라이언트 15개, 자정·관문 22개, 서버 20개, Lua 모의·대조군 15개 통과. 실제 Redis 1묶음은 실행 파일 부재로 건너뜀.
- 발급 후 장부 저장 18회 실패·4분 숨김, 저장 성공·31분 숨김, 완료 장부·표식 동시 실패·문서 종료·재진입, 다음 날 미확정 몫 보존을 모의 재현해 서버 한도 거부 0건 확인.
- 발급 전 읽기·쓰기·저장 무시·깨진 표식·미반영 완료 기록의 90조합에서 선물 링크·등록 요청 0건 확인.
- 꺼짐 객체·공유/복사 바이트 동일, 장부·등록 접근 0, 기존 JSX 동일 및 공유 전 `await` 없음 검사 통과.
- 전체 타입 검사 1회 종료 0·진단 0, `git diff --check` 통과. 타입 검사도 공용 `lockf` 잠금과 환경 파일 읽기 차단 아래 실행했다.

이번 실행의 결과는 `.logs/ux-gate/recheck.json`과 각 시험 로그에 있다. 실행기의 기존 전체 278파일 집계는 이전 결과를 합친 값이므로 이번 실행 범위로 보고하지 않는다.

## 남은 위험

완료·취소를 끝내 확인할 수 없는 발급 몫은 새날에도 남아 선물 가능 횟수가 줄어들 수 있다. 한도 불확실성을 시간 만료로 해소하지 않는 의도된 동작이다. 실제 Redis·실제 IndexedDB·실기기 공유·스토어 등록·PRO 부여는 미검증이다. 운영 플래그 조회·변경, 운영 데이터 쓰기, 브라우저 접근, 커밋·push·병합·배포는 수행하지 않는다.
