## 원인 메커니즘과 읽기 경로

기존 옵션 합계는 거래자의 의도나 신규·청산을 식별하지 않는다. FINRA 장외 비중은 ATS와 도매업자 내부체결을 포함하며 기관 순매수나 매집 의도를 식별하지 않는다. 내부자 매도 코드는 동기나 미래 악재를 입증하지 않는다. 따라서 합계·코드에서 투자 방향을 단정하는 선택지를 증거 초과로 판정한다. 콜이 풋보다 많지 않거나 내부자 사례가 실제 비파생 주식 매도가 아니라면 전제 불일치도 구분한다.

기존 API 라우트를 그대로 실행하면 옵션·내부자 캐시 미스에서 공급사를 조회하거나 Redis에 쓸 수 있다. 새 서비스는 영수증과 같이 기존 API의 동일 적재본만 읽는다.

| 기존 API | 재사용하는 읽기 경로 | 표시 |
|---|---|---|
| `/api/flow/options-eod` | `intrinio:options:eod`의 현재 판 `tickers` | 관측일·콜/풋 거래량 원값·EOD |
| `/api/flow/dark-pool` | 기존 `getDarkPoolBatchChecked` | 종목별 관측일·장외 비중/거래량 원값·FINRA 출처 |
| `/api/command/insider` | 기존 `insiderKey`가 정의하는 Intrinio 응답 캐시 | 공시일·거래일·코드·주식 수·파생 여부·SEC 링크 |

Intrinio 내부자 변환기는 미제공 10b5-1 필드를 기존에 `false`로 채운다. 새 서비스는 원본 캐시를 읽고 미제공을 `null`로 보존한다. 화면에는 자료 부족·미제공으로 명시한다. 기존 변환기·앱 표시는 바꾸지 않았다. 원천이 제공하지 않는 계획 여부를 생성하거나 공시 원문을 새로 수집하지 않는다.

옵션·장외는 관측일이 7일 이내인 자료, 내부자는 공시일과 거래일이 모두 90일 이내인 자료만 사용한다. 옵션의 과거 `stale` 판은 가져오지 않고 같은 현재 판의 다른 종목으로 대체한다. 내부자는 첫 30개 캐시 공시에서 유효한 최신 거래 한 건이며 전체 집계가 아니다. 같은 거래일에는 비파생 S 거래를 우선한다. 원천 날짜와 조회 UTC 시각을 구분하고 원천의 정확한 시각 미제공을 설명한다.

## 캐시와 공유 함수 영향

- Next `unstable_cache`로 자료 한 벌을 300초 재사용한다. 키는 종목 입력·답안·언어에 따라 늘어나지 않는다. SSR 자체는 쿼리별 동적 렌더다.
- 캐시 미스 한 벌은 기존 MGET 1회(옵션 1키 + 내부자 8키)와 FINRA 배치 읽기 1회다. 서버 인스턴스 안의 동시 미스는 같은 진행 중 작업으로 합친다.
- Next 데이터 캐시는 프레임워크 캐시이며 운영 Redis/DB 쓰기는 추가하지 않는다. 새 경로의 금융 공급사 호출 상한은 적중·결측 모두 0회다. 기존 Redis 클라이언트의 읽기 실패 대체 경로는 유지된다.
- 기존 공유 함수 수정은 없다. `insiderKey`, `getDarkPoolBatchChecked`, `mgetFromCache`, `toLoc`, `publicBase`를 호출만 한다. 기존 호출자의 소스는 기준 커밋과 동일하다.
