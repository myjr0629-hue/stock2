# 11/5 선물 재안내 운영 메모

이 변경의 배포 전에는 설정만으로 재안내할 수 없다. 기존 안내의 횟수·중단 표식은 각 기기의 localStorage에 있고 `/api/gift/config`는 회차를 제공하지 않는다. 이 브랜치는 기본 꺼짐이다. 운영 반영과 스위치 조작은 운영 세션이 한다.

- 켜기: 배포 후 **EC2 기본 Redis** 문자열 키 `gift:announce:1105`에 `1`을 설정한다. 읽기 API는 `GET /api/gift/reannounce-config`, 응답 `{"enabled":true}`다. 조회 실패·다른 값·키 없음은 꺼짐이다. 응답은 캐시하지 않는다. 이미 실행 중인 앱은 다음 마운트 때 설정을 읽는다.
- 끄기: 같은 키를 삭제하거나 `0`으로 바꾼다. 이미 떠 있는 시트는 즉시 닫히지 않는다. 기기별 회차 표식은 남기므로 같은 키를 다시 켜도 이미 본 기기는 다시 보지 않는다. 새 회차를 원하면 별도 코드 변경이 필요하다.
- 전제: `/api/gift/config`가 live이고 유효한 선물 수단이 있어야 한다. 코드의 만료 판정과 플랫폼별 재고·오퍼 유효성을 운영에서 먼저 확인한다. 11/5 기준 코드상 Play 쿠폰 종료 시각은 10/31 00:00 UTC이며 Android 선물 및 초대 보상 발급은 막힌다. iOS도 실제 코드 및 오퍼의 유효성·재고 확인이 필요하다. 이 문서는 설정 조작 또는 쿠폰 발급을 실행하지 않는다.
- 회차는 기기 localStorage `signumhq.gift.announce.1105`의 표시 시각으로 1회 제한한다. 기존 표식의 중단·3회 한도는 이번 회차에 적용하지 않되 마지막 기존 안내에서 24시간이 지나야 한다. 되돌린 뒤 기존 안내도 이번 회차에서 24시간이 지나야 한다. 저장 실패 시 표시하지 않는다. 앱 데이터 삭제·다른 기기는 별개다.
- 기존 온보딩 완료, 선물 활성화, 대시보드 3.5초 또는 실적·리포트 체류, 평점 회차·최근 요청 및 다른 모달 조건은 유지한다. 새 회차는 기존 버튼과 고지·배치를 유지하고 제목만 세 언어로 바꾼다. 기존 `gift_pop` 집계는 회차를 구분하지 않는다.

## 기존 초대자 보상

선물 링크의 익명 초대 참조와 설치 전 터치가 신규 설치 후 첫 실행의 IP/기기와 매칭되고 부정 방지 조건을 통과하면 초대자에게 크레딧 1건이 쌓인다. 정확한 IP가 없을 때 제한된 대역 매칭도 있다. 72시간 터치, 동일 IP 30일 1회, 자기 초대 차단, 초대자 최대 3건, 전체 하루 25건 상한이 있다. `INVITE_REWARD=1`일 때 선물함 조회가 초대자의 OS에 맞는 기존 일회용 코드 풀에서 크레딧을 코드로 바꾼다. 풀이 비었거나 Android 예비 60개 이하, Play 만료 등에는 대기한다. 기존 오퍼의 사용 자격과 실제 재고는 별도 확인이 필요하다. 모든 설치에 대한 지급 보장은 없다.

공유 함수 영향: `giftAnnounceBlock`·`markGiftAnnounced`는 안내 호스트만 호출하며 기본 인자는 기존 규칙이다. `readAnnounceState`는 선물 안내·탭 중단·평점 충돌 방지에서 기존 표식 그대로 사용한다. `reviewMomentBlocked`는 평점 예약 및 실행에서 호출되며 새 회차 표시 후에도 60초 차단한다.
