# 11/5 선물 재안내 운영 메모

이 변경의 배포 전에는 설정만으로 재안내할 수 없다. 기존 안내의 횟수·중단 표식은 각 기기의 localStorage에 있고 `/api/gift/config`는 회차를 제공하지 않는다. 이 브랜치는 기본 꺼짐이다. 운영 반영과 스위치 조작은 운영 세션이 한다.

- 켜기: 배포 후 **EC2 기본 Redis** 문자열 키 `gift:announce:1105`에 `1`을 설정한다. 읽기 API는 `GET /api/gift/reannounce-config`(서버 1.5초 상한), 응답 `{"enabled":true}`. 조회 실패·다른 값·키 없음은 꺼짐. 앱은 선물이 켜져 있고 이 기기가 아직 재안내를 안 봤을 때만 실행당 1번 묻고, **3초 안에 답이 없거나 실패하면 그 실행은 재안내 없음**.
- 끄기: 같은 키를 삭제하거나 `0`으로 바꾼다. 이미 떠 있는 시트는 즉시 닫히지 않는다. 기기별 회차 표식은 남기므로 다시 켜도 이미 본 기기는 다시 보지 않는다.
- 전제: `/api/gift/config`가 live이고 유효한 선물 수단이 있어야 한다(꺼져 있으면 재안내도 없다).
- **기존 안내와 분리**: 기존 안내(①대시보드 3.5초 ②실적·리포트 좋은 순간)의 코드·횟수(최대 3회)·48시간 간격·중단 표식(`signumhq.gift.announce.v1`)은 재안내가 읽지도 쓰지도 않는다. 기존 입구는 설정 조회를 기다리지 않는다 — 스위치가 꺼졌거나 조회가 늦거나 실패하면 기존 동작 그대로.
- 재안내: 기기 localStorage `signumhq.gift.announce.1105`(띄운 시각)로 기기당 1회. 기존 표식의 중단·3회 한도·48시간은 적용하지 않는다. 첫 실행(new)·대시보드/좋은 순간·평점 회차·다른 시트 조건은 기존과 같다. 저장 실패 시 표시하지 않는다.
- 겹침: 둘 사이는 «한 실행 최대 1회»만 공유한다 — 같은 실행에 기존 안내가 먼저 떴으면 재안내는 다음 실행에. 재안내를 본 뒤에도 기존 안내는 자기 규칙대로 다음 실행부터 뜬다.
- 문구: 제목만 3개 언어 «미국 주식» 관점으로 바꾼다(부제·단추·고지·배치는 기존 그대로). 집계: 띄움 `open`(gift_pop, 기존과 합산) + 띄운 곳 `re:dash|re:earn|re:report`(`scripts/mkt-gift.js` «재안내 띄운 곳»).

## 기존 초대자 보상

선물 링크의 익명 초대 참조와 설치 전 터치가 신규 설치 후 첫 실행의 IP/기기와 매칭되고 부정 방지 조건을 통과하면 초대자에게 크레딧 1건이 쌓인다. 정확한 IP가 없을 때 제한된 대역 매칭도 있다. 72시간 터치, 동일 IP 30일 1회, 자기 초대 차단, 초대자 최대 3건, 전체 하루 25건 상한이 있다. `INVITE_REWARD=1`일 때 선물함 조회가 초대자의 OS에 맞는 기존 일회용 코드 풀에서 크레딧을 코드로 바꾼다. 풀이 비었거나 Android 예비 60개 이하, Play 만료 등에는 대기한다. 기존 오퍼의 사용 자격과 실제 재고는 별도 확인이 필요하다. 모든 설치에 대한 지급 보장은 없다.

공유 함수 영향: `giftAnnounceBlock`·`markGiftAnnounced`·`readAnnounceState`는 원본 그대로다(재안내는 별도 `giftReannounceBlock`·`markGiftReannounced`). `reviewMomentBlocked`는 재안내 표시 뒤에도 60초 평점 요청을 미룬다(재안내 표식이 없으면 기존과 같다).
