# RevenueCat 체험 코호트 (서버 전용)

운영 설정은 코디네이터가 수행한다. 웹훅 URL은 `/api/webhooks/revenuecat`, RevenueCat의 Authorization 헤더 전체 값은 `REVENUECAT_WEBHOOK_AUTH`, 별도 무작위 서버 HMAC 키는 `RC_COHORT_HMAC_SECRET`에 설정한다. 기존 Upstash REST 설정도 필요하다. 두 비밀값은 클라이언트에 노출하지 않는다. HMAC 키를 바꾸면 이전 기록과 새 기록을 연결할 수 없다.

수신은 인증 실패 401, 잘못된 입력 400, 크기 초과 413, 설정·저장 실패 503으로 응답한다. 성공 또는 중복은 200이다. 503은 공급자 재전송이 필요하며 실패와 미수신 건을 이 저장소만으로 계산할 수 없다. 로그에 본문·식별자·오류 객체를 남기지 않는다. 테스트 환경 이벤트는 저장하되 조회에서 제외한다. 식별자와 거래·이벤트 ID는 서로 다른 용도의 HMAC으로만 기록한다. 원문과 원 ID는 저장하지 않는다. 각 이벤트 키는 최초 수신 120일 후 만료하며 중복은 TTL을 연장하지 않는다. 일별 수신 건수는 식별자 없는 원자적 수신 집계다.

조회: `node scripts/rc-cohort.mjs 2026-10-01 2026-11-01` (UTC 시작 포함·끝 제외). Redis 읽기만 사용한다. 체험 시작 이벤트가 분모이며 유료 갱신은 같은 가명 사용자·원 거래의 체험 종료 이후 NORMAL RENEWAL로 센다. 종료 시 갱신 켬은 유료 갱신으로 확인된 건만, 끔은 해당 종료와 해지 신호가 뒷받침된 건만 센다. 그 외 종료 건은 미확정이다. 재체험과 CUSTOMER_SUPPORT 환불 신호는 보존된 기록 기반의 하한·대리 지표다. 계정 이전, 다른 app_user_id, 거래 ID 누락, 수신 누락, 120일이 지난 기록은 정확한 연결을 보장하지 못한다. 늦은 이벤트가 도착하면 결과가 바뀔 수 있다. PRO 사용은 미측정이다. 최초 설정 전 기록은 포함되지 않는다. 조회는 스냅샷이 아니며 만료 또는 동시 수신에 따른 차이가 가능하다.
